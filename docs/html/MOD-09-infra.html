1背景与目标

MOD-09 是 Spec §6 依赖矩阵中唯一不被任何人阻塞、却阻塞所有人的模块。它要对抗的是三种最容易在早期发生的腐化：各模块自建日志格式、各自调用全局随机、各自写 runs/ 目录——这三件事一旦发生，可复现性与 INV-6 同时失效。

本模块的存在理由是把工程横切关注点从领域逻辑里彻底剥离，体现为四件事：

  1. 可复现——run_id + config_hash + 环境固定，任意一次 run 可用一条命令重放；对抗「结果无法归因到配置」。
  2. 可观测——唯一 JSONL 落地实现，轨迹行 schema 严格对齐 Spec §4.5；对抗「各模块自建日志、指标无法聚合」。
  3. 可审计——集中 redaction + 错误码注册表 + 泄漏审计的落盘出口；对抗 INV-5 被日志侧绕过。
  4. 可拦截——guards.py 用 AST 静态扫描把 INV-1/INV-6 变成可执行门禁，而不是口头纪律。
成功度量：① 同一 AppConfig 两次 config_hash() 完全一致；② 轨迹行 schema 校验通过率 100%；③ guards 在故意埋雷的 fixture 上 100% 报出违例；④ 进程被 SIGKILL 后，已落盘轨迹行的 JSON 完整性 100%（最多丢最后一行）。

2范围

✓ 负责范围内
  • configs/*.yaml 加载、优先级合并、schema 校验、config_hash 计算、配置快照落盘。
  • run_id 生成规则与 runs/<run_id>/ 目录树初始化（对齐 Spec §5）。
  • JsonlWriter：追加写、逐行 flush、崩溃安全、轮转；事件类型枚举与事件 schema。
  • 单步轨迹行落盘与 schema 校验（对齐 Spec §4.5），含 heldout/test seed 自动 redaction。
  • CLI 子命令树（Spec §4.6）、参数解析、退出码约定、--dry-run / --resume 透传。
  • 绘图：代际指标曲线与熵曲线输出到 runs/<run_id>/plots/。
  • git 操作封装：worktree_clean_check / commit_harness / tag_version / rollback_to。
  • guards.py：确定性扫描（INV-6）与分层 import 门禁（INV-1），可独立运行并接入 CI。
  • 错误码注册表：E_ENV_* / E_ACTION_* / E_LLM_* / E_EVOLVE_* / E_EVAL_* / E_IO_* 集中定义与含义表。
  • 进程级确定性环境固化（PYTHONHASHSEED=0、时区、locale、线程数）。
✗ 不负责（范围外）
  • 任何领域逻辑（不得在 infra 里写游戏或评估规则）——逐字复用 Spec §3 MOD-09 的「不负责」清单。
  • 不定义指标口径与统计方法（MOD-08）。
  • 不生成演化候选、不做接受判定（MOD-07）。
  • 不组装 prompt（MOD-04）。
  • 不做观测投影与泄漏判定的判定逻辑（MOD-02，本模块只提供落盘出口与 redaction 的兜底）。
  • 不选择与加载模型（MOD-03）。
  • 不实现游戏规则（MOD-01）。
  • 不实现闭环状态机与断点语义（MOD-06，本模块只提供 state.json 的读写原语）。

典型场景

  1. 冷启动 loop run --generations 3 --k 30（初始化 run 目录 → 每步写轨迹 → 每代写报告）。
  2. 事故复现（拿 run_id 重放）。
  3. CI 跑 guards 拦下越权 import。
  4. 演化前 git 门禁。
  5. 崩溃后 --resume。

4功能需求

每条 FR 编号可测试，事实与 PRD 逐条对齐。

FR-09-1配置优先级（Spec v1.4 B-26）：合并顺序为 CLI 显式参数 > GAMERSI_* 环境变量 > harness/config.json（可演化层）> configs/default.yaml > 代码内 dataclass 默认值。harness 层只接受白名单键（policy.* 训练期采样参数、memory.retrieve.*、agent.tools.*），出现其他键或试图设置评估温度 → E_IO_CONFIG_INVALID（退出码 2）；这一层计入 artifact_hash，不计入 config_hash。环境变量命名规则 GAMERSI_<SECTION>__<KEY>（双下划线分层），未知键 → 记 E_IO_CONFIG_UNKNOWN 并忽略（不中断），未知键清单写入 run 启动日志。

FR-09-2schema 校验：AppConfig 为 frozen dataclass + 显式 validate()（避免引入 pydantic 作为阶段一硬依赖）；类型不符或越界 → E_IO_CONFIG_INVALID 并以退出码 2 终止，错误信息必须指出键路径与期望类型。

FR-09-3config_hash：config_hash = sha256(json.dumps(_canonical(cfg), sort_keys=True, separators=(",",":"), ensure_ascii=False))[:16]。_canonical 排除易变字段（run_id、created_at、log_level、paths.runs_root）与所有绝对路径，不包含 harness_version（Spec v1.3 B-19：否则第一代被接受后 --resume 必然冲突）。harness 的变化由 artifact_hash(harness_dir) 表达：对 (相对路径, 文件 sha256) 按路径排序后整体 sha256，逐代写入 version.json 与 report。

FR-09-4run_id：run_id = f"{git_short_sha}-{config_hash[:8]}-{utc_ts}"，utc_ts = YYYYMMDDTHHMMSSZ；git_short_sha 取自 git rev-parse --short HEAD，仓库不可用（无 git / dirty 之外的情况）→ 用 nogit 占位并记 E_IO_GIT_UNAVAILABLE。已回填（Spec v1.3 §4.6）：--run-id 显式指定时以显式值为准，用于复现与测试。

FR-09-5目录初始化：init_run_dir(run_id, cfg) -> RunPaths 幂等创建 Spec §5 的目录树（config.json、events.jsonl、episodes/<split>/、reflections/、generations/、metrics/、plots/、audit/）。目录已存在且 config.json 的 config_hash 不一致 → E_IO_RUN_CONFLICT 并退出码 2（禁止两套配置写同一 run）。

FR-09-6JsonlWriter 写入语义：每行 json.dumps(..., ensure_ascii=False) + \n；每次 write() 后 flush()；infra.fsync_every（默认 0 = 不 fsync，>0 表示每 N 行 os.fsync）。崩溃安全：读取端必须容忍末行截断（json.JSONDecodeError 时丢弃最后一行并记 E_IO_TRAILING_TRUNCATED）；写入端保证「一行要么完整要么不存在」——先构造整行字符串再单次 write。

FR-09-7事件注册表（Spec v1.3 §8.2）：事件名为 <module>.<event>，全部登记在 infra/events.py::EVENT_REGISTRY（§6.5），统一落到 runs/<run_id>/events.jsonl；通过 emit(event, **fields) 写入，自动附加 ts/run_id/module。未登记的事件：开发模式抛 E_IO_EVENT_UNKNOWN；生产模式改写为 infra.unknown_event 并保留原名。轨迹行不是事件，走 JsonlWriter 写入 episodes/。

FR-09-8轨迹行 schema：字段严格对齐 Spec v1.3 §4.5，schema 文件为 schemas/trajectory_line.schema.json（§6.2）。已登记字段之外只允许 x_ 前缀字段（additionalProperties:false + patternProperties）；缺必填字段 → E_IO_TRAJECTORY_SCHEMA；局末的 episode_end 行用独立的 schema 分支校验；ts 统一为 UTC ISO-8601，带 Z。

FR-09-9redaction（作用域收窄，Spec v1.3 B-19）：Redactor 持有由 MOD-02 审计器注册的敏感值集合（heldout/test seed、canary 串、GameState 专有键名）。只作用于 agent 可见的三个出口：prompts/ 快照、memory/ 与 reflections/，落盘前做值级替换（如 <REDACTED:seed>）并计数。命中数 > 0 → 写 infra.redaction_hit 事件并触发 MOD-02 告警回调（这类命中本身说明发生了 INV-5 泄漏）。轨迹（episodes/）、events.jsonl、generations/ 不做 redaction——它们属于审计侧，MOD-08 的配对检验需要原始 seed。只擦除不阻断，阻断属于 MOD-04/MOD-02 的职责。

FR-09-10CLI 一致性：子命令树与 Spec v1.3 §4.6 逐字一致，包括 inference *、loop status|smoke、eval ablation|test、memory *、guards check。run 一律用 --run-id ID 指定，续跑用 --resume 开关。本模块只负责解析与转发到各模块的 register(subparser)；新增命令必须同步更新 Spec §4.6。

FR-09-11退出码：0 成功（含 HITL 挂起）；1 领域失败（如验收不达标）；2 配置/环境错误；3 模型不可用；4 沙箱/守卫违例；5 IO 落盘失败；130 用户 Ctrl-C（与 Spec v1.3 §8.3 一致）。约定写入 gamer_rsi/infra/exit_codes.py 并被所有命令复用。

FR-09-12dry-run 与 resume：--dry-run 对所有命令生效——不调用模型、不写 runs/、只打印将执行的动作与配置摘要（stdout 为可解析 JSON）；--run-id ID --resume 由 MOD-06 实现语义，本模块负责定位目录、校验 config_hash 一致（config_hash 不含 harness，所以演化过的 run 也能续跑），并在 state.json 缺失时报 E_IO_STATE_MISSING。

FR-09-13绘图：plot_generations(csv_path, out_dir) 输出 win_rate.png、stages_cleared.png、hearts_left.png、entropy.png、train_heldout_gap.png（INV-7 口径，Spec v1.3），每图含 n、ci95 误差棒与数据点标注；无 matplotlib 时降级为 E_IO_PLOT_UNAVAILABLE 警告而不失败。

FR-09-14git 封装：worktree_clean_check() 在有未提交改动时抛 E_IO_GIT_DIRTY（演化前门禁）；commit_harness(version, message) 提交 harness/ 并返回 commit sha，提交信息格式 harness(v{N}): {message}；tag_version(N) 打 harness-v{N} 轻量 tag（已存在则跳过；不建同名分支，避免 refname is ambiguous）；rollback_to(N) 以 git checkout harness-v{N} -- harness/ 恢复工件目录并返回新 commit sha。

FR-09-15确定性守卫（AST，非正则）：scan_determinism() 报出 E_IO_GUARD_RANDOM（import random / numpy.random.* 未显式 seed / time.time() 参与采样 / uuid4() 用于标识 id）；scan_layer_imports() 报出 E_IO_GUARD_LAYER（gamer_rsi/agent|memory|loop|evolve|evals/* 中出现 import gamer_rsi.env，违反 INV-1）。白名单注释 # guard: allow <CODE> reason=... 可豁免，但会记 guard_finding 事件留痕。

FR-09-16错误码注册表：gamer_rsi/infra/errors.py 集中定义全部 E_* 枚举 + 含义表 + 默认退出码映射；禁止其他模块自定义字符串错误码。

FR-09-18schema 与原子写：schemas/*.schema.json 由本模块登记并提供 validate(name, obj)；write_json_atomic(path, obj)（tmp + os.replace）是 report.json、state.json、version.json 唯一的写入口。

FR-09-19git 忽略检查：init_run_dir 检查 runs_root 已被 .gitignore 覆盖（git check-ignore），否则记 E_IO_RUNS_NOT_IGNORED 并退出码 2，防止 worktree_clean_check() 永远判定为 dirty。

FR-09-17进程确定性环境：bootstrap_process() 设置 PYTHONHASHSEED=0（若未设置则 re-exec 一次）、TZ=UTC、LC_ALL=C.UTF-8，并把 infra.threads=1 传给后端；设置内容经 process_snapshot() / process_fingerprint() 由真正的 infra.run_start 事件记录（cli.cli_init_run()，此时配置与 sink 都已就绪）。bootstrap_process() 自身不发事件：它在 main() 最开头执行，既没有 config_hash 也没有 events sink，早发只会产生一条缺必填字段、且必然被丢弃的 run_start（v0.3.1 修复）。

5非功能需求

NFR-09-1崩溃安全：SIGKILL 后已落盘行 100% 可解析；末行截断可检测（E_IO_TRAILING_TRUNCATED）。

NFR-09-2性能：单次 write() p99 < 1 ms（本地 SSD，不含 fsync）；load_config() < 50 ms；不得成为单步决策的瓶颈（单步预算见 MOD-04）。

NFR-09-3确定性：config_hash、run_id 中除时间戳外全部稳定；derive_seed 对同一输入返回同一 64-bit 整数，且与进程、平台、PYTHONHASHSEED 无关（内部用 hashlib.blake2b 而非 hash()）。作用域：只用于 agent 侧随机（采样 seed、bootstrap、候选 id）；环境侧的流派生由 MOD-01 按 GAME-01 §3 的 xmur3 + SplitMix64 实现，两者互不替代。

NFR-09-4可观测：任何失败必须带错误码 + 人类可读信息 + 复现命令三要素。

NFR-09-5依赖方向单向：infra 不 import 任何其他 gamer_rsi 子包（除 errors 自身）；guards 对此做静态检查。

def bootstrap(argv):
    bootstrap_process()                       # FR-09-17: PYTHONHASHSEED/TZ/locale/threads
    cfg = load_config(cli_overrides=parse_cli(argv))     # FR-09-1/2
    if "--dry-run" in argv:
        return print(json.dumps({"config": canonical_json(cfg),
                                 "plan": plan_of(argv)}))   # 只打印，不落盘
    run_id = make_run_id(cfg, explicit=arg("--run-id"))  # FR-09-4
    paths = init_run_dir(run_id, cfg)                    # FR-09-5
    redactor = Redactor(); mod02_audit.register_sensitive(redactor)   # FR-09-9
    events.bind(paths.root / "events.jsonl", run_id)             # FR-09-7
    events.emit("infra.run_start", config_hash=config_hash(cfg), git_sha=git_sha())
    return paths, cfg, redactor                                  # redactor 只交给 prompt/memory/reflection 写入方

10错误处理与降级

错误码触发处理
E_IO_CONFIG_INVALIDschema 校验失败打印键路径 + 期望类型，退出码 2
E_IO_CONFIG_UNKNOWN未知配置键忽略并告警，记入 run_start
E_IO_RUN_CONFLICT同 run_id 不同 config_hash退出码 2，提示改用 --run-id 或新目录
E_IO_STATE_MISSING--resume 但无 state.json退出码 2
E_IO_TRAJECTORY_SCHEMA轨迹行缺字段/类型错开发期抛异常；生产写 illegal 兜底行并计数
E_IO_EVENT_UNKNOWN事件名不在 EVENT_TYPES同上
E_IO_TRAILING_TRUNCATED读到最后一行 JSON 不完整丢弃该行并告警（不中断）
E_IO_REDACTION_HIT落盘前擦除命中写 guard_finding + 触发 MOD-02 告警
E_IO_DISK_FULL写入 OSError立即停止 run，保留已落盘数据，退出码 5
E_IO_RUNS_NOT_IGNOREDruns/ 未被 .gitignore 覆盖退出码 2
E_IO_GIT_DIRTY / E_IO_GIT_UNAVAILABLEgit 门禁失败 / 无 git前者阻断演化；后者降级为 nogit
E_IO_GUARD_RANDOM / E_IO_GUARD_LAYER守卫检出违例退出码 4；演化场景直接拒绝候选
E_IO_PLOT_UNAVAILABLE缺 matplotlib降级为警告
降级原则：可观测性缺失（绘图、git、fsync）→ 降级 + 告警；可复现性缺失（config 非法、run 冲突、守卫违例）→ 立即失败，绝不静默继续。
