MOD-07 · evolve

演化引擎 —— 让 agent 改写自己的 harness，由环境 ground-truth 决定去留

RSI 闭环中最危险的一段：MOD-06 每 K 局（默认 30）触发一次演化周期，MOD-07 负责生成候选改动、在 train 上冒烟、在 heldout 上正式评估，再用一张六项判定表决定 accept 还是 reject。设计重心不是"生成更聪明的改动"，而是在结构上掐死自我确认环路。

版本 v0.3 状态：待评审 里程碑：M2 → M3 作者：GameRSI 技术文档 日期：2026-09-30
背景与目标
承接 MOD-06 的演化周期，把「策略记忆 + 最近轨迹 + 反思」变成可评估的 harness 改动；六大可验收目标覆盖候选生成、双阶段评估、判定表、版本化、HITL 与报告。
核心职责
候选生成与去重、改动面合法性校验、train 冒烟 → heldout 正式评估的编排、判定表裁决、不可变版本化与回滚、HITL 门禁、代际报告。
服务对象
MOD-06 loop（主调用方）、MOD-08 evals（被调用方，提供指标与统计）、MOD-02 env-sandbox（静态扫描与受限加载）、人类操作者（HITL 审批）。
关键成功度量
判定表六项全过才 accept；每次 accept 必有不可变版本 + git commit；任意 reject 必有 report.json；恶意候选在静态扫描阶段被挡且 0 局 heldout 消耗。

1背景与目标

MOD-06 每 K 局（默认 30）触发演化周期，把「策略记忆 + 最近轨迹 + 反思」交给 MOD-07。MOD-07 负责 RSI 闭环中最危险的一段：让 agent 改写自己的 harness，并由环境 ground-truth 决定改动去留。按 RSI 调研 §4 的失败模式，设计重心不是"生成更聪明的改动"，而是在结构上掐死自我确认环路：

  • 自我确认环路：候选生成阶段物理上看不到 heldout/test 数据（INV-5），裁判只看环境原生结果（INV-7），生成者与裁判者上下文不重叠。
  • 模型坍缩：接受判定强制 collapse_flag == False + 熵斜率下限（C4）。
  • 过度优化/指标刷分：改动面硬上限 + win_rate_gap 阈值 + 消融对照（M3）。

目标（可验收）

  1. propose() 稳定产出 2–3 个通过校验的候选，或返回显式空结果 + E_EVOLVE_NO_CANDIDATE，绝不静默退化；
  2. 每个候选走「train 冒烟 → heldout 正式评估」，同 seed 同结果；
  3. 判定是可执行判定表（§8.2），六项全通过才 accept；
  4. 每次 accept 产生不可变版本记录 + git commit；
  5. HITL 开启时挂起等 evolve approve|rollback；
  6. report.json 逐字段对齐 Spec §4.5 并通过 round-trip 测试。

2范围

这个模块"只管把改动安全地落地并裁决"，不管推理、不管统计、也不评判 harness 内容的语义。职责边界如下：

✓ 负责（范围内）
  • propose()：候选生成 / 去重 / 证据束白名单
  • 候选合法性校验：MOD-02 AST 扫描、改动面计数、禁用符号、JSON Schema
  • evaluate_candidate()：train 冒烟 → heldout 正式评估，只编排 MOD-08
  • judge() 判定表与 reason
  • versioning.py：harness/versions/v{N}/、version.json 血缘、diff.patch、git commit + tag harness-v{N}、rollback
  • gate.py：HITL 挂起 / 恢复 / 超时回滚
  • 代际日志与 report.json
  • E_EVOLVE_* 错误码的产生与上报（登记由 MOD-09 完成）
✗ 不负责（范围外）
  • 模型推理实现（MOD-03）
  • 指标定义与统计口径（MOD-08）
  • seed 抽取规则（MOD-09 注册表 + MOD-08 协议）
  • 不改 gamer_rsi/agent/policy.py 的解析与校验逻辑（MOD-04）
  • 不做超参搜索
  • 不做 LoRA/微调（MOD-10）
  • 不决定 harness 内容的语义，只负责把 LLM 给出的 diff 落盘并版本化

4功能需求

每条需求都可单独测试，编号沿用 PRD。

  • FR-07-1候选生成：propose() 输入 EvidenceBundle，输出 list[Candidate]，长度 ∈ [1, evolve.n_candidates]（默认 2，上限 3）。每条含 kind ∈ {prompt_patch, tool_patch, config_patch}、diff（unified diff）、rationale（≤300 字）、expected_effect{metric,direction,priority}。失败返回 ProposalResult(candidates=[], error_code="E_EVOLVE_PROPOSE_FAILED")。
  • FR-07-2证据束白名单：EvidenceBundle 只能由 trajectory_summary(split="train")、memory.retrieve_for_evolution()、reflection_set(split="train")、harness_snapshot() 构造；build_evidence_bundle() 是唯一构造函数，__post_init__ 校验 source_tags ⊆ {"memory:train","traj:train","reflect:train","harness:current"}。
  • FR-07-3防自我确认（生成侧）：证据束条目 split 必须全为 train；assert_no_holdout_leak() ① 拒绝任何 split != "train" 条目，② 对全部文本字段做 seed 字面量扫描——命中 heldout 注册表任一 seed 的整值 token（正则 (?<!\d){seed}(?!\d)）即抛 E_EVAL_INV5_LEAK，③ 拒绝出现 heldout/test 标签或 seeds.yaml 片段。render_proposer_prompt() 模板化产出，不允许插入证据束之外的上下文（INV-3）。
  • FR-07-4修改面硬约束（单候选）：改动行数 ≤ evolve.max_diff_lines（40）且字符数 ≤ evolve.max_diff_chars（4000）；文件数 ≤ 2 且必须 ∈ 白名单 harness/prompts/decision.md、harness/prompts/reflection.md、harness/tools/*.py、harness/config.json；禁止改 rank_actions 签名与 @harness_tool 语义；禁止新增第三方依赖；禁止网络/文件写/subprocess/env 内部访问（INV-4）；config_patch 只能改 evolve.evolvable_keys 声明的键。
  • FR-07-5去重与排序：按归一化 diff 的 sha256 去重；按 expected_effect.priority 降序、同优先级 candidate_id 升序（保证确定性）。
  • FR-07-6训练冒烟：冒烟 seed 取本代训练块的末 5 个（evals.seeds.take("train", generation=g)[-5:]），不再固定用 1000–1004。parent 在同一组 seed 上的冒烟结果 parent_smoke 与 parent heldout 一起计算。快速淘汰条件（任一命中即写 E_EVOLVE_SMOKE_FAILED）：冒烟胜率 < parent_smoke 胜率 − 0.2；非法率 > 0.30；fallback 率 > 0.30；harness 运行期异常。
  • FR-07-7正式评估：冒烟通过者在 evolve.heldout_seeds（默认 heldout:2000-2039，40 局）评估，预算与当前版本完全相同（同 seed 集合、同 episode_config、同采样参数，仅 prompt_tokens 允许差异并记录）；指标全部委托 MOD-08 evaluate_arm()；parent 与候选必须使用同一个冻结的记忆快照 memory_version，所以 parent 每代都要重新评估。MOD-07 不做任何统计运算。
  • FR-07-8判定表：按 §8.2 顺序短路求值，六项全 True → accept，否则 reject 且 reason 含首个失败条件 id（如 C2:heldout_win_rate 0.28<0.32）。
  • FR-07-9版本化：accept() 生成 harness/versions/v{N}/（全量拷贝 + version.json + diff.patch），更新 harness/version.json 指针，经 MOD-09 commit_harness 提交到当前分支并打 tag harness-v{N}（不建同名分支，Spec B-22），message = harness(v{N}): gen-{G} {kind} {short_rationale}；N = 现有最大 +1，不可复用、不可重写历史。
  • FR-07-10回滚：rollback(to_version) 用 versions/v{to_version}/ 覆盖 harness/，写 version.json、生成 revert.patch、提交 revert(harness): back to v{N}，并写一条 decision="rollback" 的代际报告。
  • FR-07-11HITL 门：evolve.hitl=true 时 gate.await_human() 把决策置 pending、写 gen-{N}/gate.json（generation, harness_version, parent_version, diff_path, report_path, status, expires_at），loop 优雅退出（exit 0，可续跑）；evolve approve|rollback --generation N 读取 gate 文件后执行 accept/rollback，写 decided_by="human" 与可选 reason；超时（默认 24h）→ 保守回滚 parent_version，reason="hitl_timeout"（对齐 Spec §8.5）。
  • FR-07-12拒绝记录：任何 reject（含冒烟淘汰、扫描失败）都落 gen-{N}/candidates/{candidate_id}.json，含 candidate、report（若有）、decision、reason、error_code。
  • FR-07-13候选代码安全执行：新 harness 使用前必须依次通过 guard.gate()（MOD-02 静态扫描）与 guard.load_harness_tools()（子进程 worker 加载，Spec B-20）；扫描失败 → 直接 reject，E_EVOLVE_SCAN_FAILED，不进冒烟、不进 heldout；受限加载失败 → 立即回滚 parent_version，E_EVOLVE_LOAD_FAILED。
  • FR-07-14代际报告：每 gen-{N} 写 report.json，键严格等于 Spec §4.5、缺失用 null、不新增顶层键；多候选时记录最终接受者（或最后尝试者），其余写 candidates/ 明细。
  • FR-07-15空候选/全淘汰也必须落盘（decision="reject" + 对应错误码），保证「每次接受/拒绝都有 report.json 支撑」（Spec §8.4）。

5非功能需求

  • NFR-07-1确定性：随机性只来自显式 seed（evolve.seed，由 MOD-09 从 run_id 派生）；禁 random.*/time/uuid4，遍历用 sorted()。同 (run_id, generation, seed) 重跑，candidate_id 序列与 report.json 逐字节相同（created_at/ts 由 MOD-09 注入，可用 --freeze-time 冻结以支持 G3）。
  • NFR-07-2安全（INV-4/INV-5）：候选代码永不 exec 于主进程；受限加载由 MOD-02 提供；proposer 上下文白名单由 FR-07-3 代码级强制；heldout seed 值出现在 harness/、runs/*/reflections/ 或 memory 库中即为 P0。
  • NFR-07-3可复现：每次决策可由 report.json + candidates/*.json + diff.patch + version.json 离线重建；config_hash 覆盖 evolve 配置（Spec §5）。
  • NFR-07-4可观测：只用 MOD-09 结构化事件（evolve.propose|validate|scan|smoke|evaluate|decision|version|gate|cost），一次调用 = 一行 JSONL，不自建日志格式。
  • NFR-07-5成本：候选共享同一 seed 集合只是配对设计，并不减少局数：单代评估局数 = H + S + C·(S + H)。默认 C=2、S=5、H=40 时为 135 局；再加训练 K=30，每代约 165 局，与 Spec §8.6 的 E_gen 一致。本模块不再单独设成本上限，超出 loop.max_episodes_per_generation 时由 MOD-06 拒绝启动。
  • NFR-07-6幂等可续跑：accept()/rollback() 以 (run_id, generation) 为幂等键，重复调用返回首次结果，不产生第二个版本号。
  • NFR-07-7失败保守：裁判链路任何异常（MOD-08 抛错/报告缺字段/超时）→ 一律 reject 并保留 parent_version，记 E_EVOLVE_JUDGE_FAILED；演化失败不得中断 play。

6.3 report.json（引用唯一 schema）

schema 为 schemas/generation_report.schema.json（Spec v1.3 §4.5），本模块不维护副本。本模块只负责填写 candidates[]、decision、decided_by、reason 四段，与 MOD-08 返回的指标段合并后，交给 MOD-09 write_json_atomic 落盘。

  • generation ≥ 1（gen-000 是 v0 基线，由 MOD-06 调用 MOD-08 生成）。
  • verdict 的枚举以 MOD-08 为准：real_gain|null|overfit_suspect|regress|insufficient。

def run_generation(run_id, gen, cfg) -> dict:
    parent = versioning.load_version(current_version())
    mem_v = memory.snapshot(version=gen)                                                  # 冻结记忆快照，parent 与候选共用
    bundle = build_evidence_bundle(run_id=run_id, n_traj=cfg.evolve.n_traj, cfg=cfg)      # FR-07-2/3
    prop = propose(bundle, cfg=cfg, rng_seed=derive_seed(run_id, gen, "propose"))
    if not prop.candidates:
        return finish(gen, parent_ho=None, reports=[], winner=None, error=prop.error_code)
    smoke_seeds = evals.seeds.take("train", generation=gen)[-5:]
    parent_ho = evals.evaluate_arm(parent.dir, split="heldout", basket="H1", memory_version=mem_v, arm="parent", run_id=run_id)
    parent_smoke = evals.evaluate_arm(parent.dir, split="train", basket=smoke_seeds, memory_version=mem_v, arm="parent", run_id=run_id)
    reports, winner = [], None
    for cand in sorted(prop.candidates, key=lambda c: (-c.expected_effect.priority, c.candidate_id)):
        staging = versioning.stage_candidate(cand, run_id=run_id, cfg=cfg)
        if validate_candidate(cand, cfg=cfg).status == "fail":                    # FR-07-4
            reports.append(reject(cand, "E_EVOLVE_PATCH_INVALID")); continue
        if guard.gate(staging).status == "fail":                                 # FR-07-13
            reports.append(reject(cand, "E_EVOLVE_SCAN_FAILED")); continue
        arm = f"cand-{cand.candidate_id}"
        smoke = evals.evaluate_arm(staging, split="train", basket=smoke_seeds, memory_version=mem_v, arm=arm, run_id=run_id)
        if smoke_fast_reject(smoke, baseline=parent_smoke, cfg=cfg):             # FR-07-6
            reports.append(reject(cand, "E_EVOLVE_SMOKE_FAILED")); continue
        ho = evals.evaluate_arm(staging, split="heldout", basket="H1", memory_version=mem_v, arm=arm, run_id=run_id)
        paired = evals.compare_paired(ho, parent_ho)
        cr = CandidateReport(cand, smoke, ho, paired); cr.verdict = judge(cr, parent_ho, cfg=cfg)
        reports.append(cr)
        if cr.verdict.decision == "accept" and (winner is None or better(cr, winner)): winner = cr
    return finish(gen, parent_ho, reports, winner)

def better(a: CandidateReport, b: CandidateReport) -> bool:   # §8.2：C2 delta 大者优先，并列时 candidate_id 小者优先
    return (a.paired.delta, -ord_id(a)) > (b.paired.delta, -ord_id(b))

def finish(gen, parent_ho, reports, winner, error=None) -> dict:
    gate_state = gate.await_human(generation=gen, winner=winner, cfg=cfg) if winner else None
    if gate_state and gate_state.status == "approved": versioning.accept(winner.cand, winner.verdict, run_id=run_id, cfg=cfg)
    elif gate_state and gate_state.status == "rejected": versioning.rollback(parent.version, run_id=run_id, reason=gate_state.reason, decided_by="human")
    report = {**evals.evaluate_generation(gen, parent_ho, winner and winner.heldout, run_id=run_id),
              **build_decision_sections(gen, reports, winner, gate_state)}          # pending 时 decision="pending"
    infra.io.write_json_atomic(paths.generation(gen) / "report.json", report)        # MOD-09 校验 schema + sha256
    return report

8.2 接受判定表（短路求值，逐条写 condition_trace）

这是整个模块的"法官"：六项按顺序短路求值，全 True 才 accept，任一项失败即 reject 并把首个失败条件写进 reason。

#条件表达式不满足时 reason / 错误码
C0前置完备report.heldout.n >= cfg.evolve.min_heldout_n 且关键字段非 nullC0:incomplete_report / E_EVOLVE_JUDGE_FAILED
C1主指标不降report.win_rate >= parent.win_rate - cfg.evolve.win_rate_tol（tol=0.0，不允许下降）C1:win_rate {v}<{p} / E_EVOLVE_NO_GAIN
C2至少一指标显著提升paired.significant == True and paired.direction == "up"，metric ∈ {win_rate, mean_stages_cleared, mean_hearts_left}，方法与口径全部由 MOD-08 compare_paired 决定（胜率用 McNemar，连续量用配对 bootstrap B=10000）C2:no_significant_gain / E_EVOLVE_NO_GAIN
C3增益真实性train.win_rate - heldout.win_rate <= cfg.evolve.gap_threshold（0.15，对齐 Spec §4.5 gap_threshold）C3:gap {gap}>{thr} / E_EVOLVE_OVERFIT_SUSPECT

12验收标准（DoD）

对齐 Spec §9 质量门 G1–G6，以及 M2/M3 里程碑与模块专属标准。

  • G1：proposer.py/judge.py/versioning.py（判定表与 diff 计数为纯函数）覆盖率 ≥80%，gate.py ≥60%（含 IO）。
  • G3：同 run_id + --freeze-time 重跑，candidate_id 序列与 report.json（除 created_at）逐字节相同。
  • G4：自测 run 上 audit leak 0 告警，MAL-5 蜜罐式候选必须被 guard.gate 抓到。
  • G5：report.json/version.json/gate.json/Candidate 四个 schema 有 round-trip 测试。
  • G6：本节命令可直接复制执行成功。
  • 对齐 M2：python -m gamer_rsi loop run --generations 1 --k 30 --hitl 闭环跑通 ≥1 轮演化，产出 diff.patch + report.json + gate.json，evolve approve 后 harness/version.json.version == 1。
  • 对齐 M3：≥3 代演化，heldout 主指标单调不降，并且至少有 1 次 accept（否则「每代都拒绝」也能满足单调不降，属于退化通过），报告写明接受率；至少 1 个指标相对基线可归因提升且 ablation.no_self_edit 差异被记录；win_rate_gap < gap_threshold 且 collapse_flag == False。
  • 专属 DoD：任意 reject 都有 report.json；任意 accept 都有 version.json + diff.patch + git commit；任意恶意候选都在静态扫描阶段被挡且 0 局 heldout 消耗。
