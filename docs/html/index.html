01一句话看懂闭环

每一代是一次完整实验。训练局只碰 train seed；门禁用独立的 held-out 篮子；test 只在一个里程碑消耗一次（INV-5）。
RSI 的难点不是“让模型改代码”，而是“改完怎么知道它真的更好”。所以本项目的重心一半在进化（MOD-07），一半在测量与判据（MOD-08）：候选补丁先过冒烟，再在 held-out 上做配对比较，最后按 C0–C5 六道条件裁决。

02分层与依赖

依赖只向下。L1+ 不得 import dice_ratchet.env.*；infra 不得 import 任何其他子包；跨层调用经 Spec §4.7 的签名表。

04当前进展：首个 accept，但账本要纠正

2026-10-17 的 m3r2 是项目第一次出现 accept：起点 0.05 → 第 1 代候选 0.275。但随后发现起点本身有问题——人工去重的 P1 从未过门禁，却被装成了 version 0 的“基线”。

已经发生的产物不重写。m3r2 的 v1 保留为“含 P1 的 provisional v1”；在役 harness（version 3）暂不动，等 v0+P2 测完一次性纠正。

新增：loop baseline

只测一个给定 harness 的 held-out，落报告与臂归档后停下——不训练、不演化、不提交 git。幂等，重复调用不重复花钱。

新增：起点守卫

loop run 起跑前，起点的 play_hash 必须是原始 v0 或任一已接受快照，否则 E_EVOLVE_UNGATED_START（退出码 2），一局都不跑。

顺序：先免费，后付费

git 干净检查（退出码 4）→ 起点守卫（退出码 2）→ gen-000 基线（开始花钱）。两条前置都不过就不产生费用。

为什么 P1 的教训重要。如果不守住“起点必须被裁决过”，闭环会稳定地在错误基线上演化：每一代都“有提升”，但相对真正的 v0 可能是倒退。守卫只能保证“没裁决过的东西不会悄悄变成父代”，它不能替代门禁本身。

06怎么读这套讲解

想理解系统

从本页的闭环图与分层图开始，按 L0 → L1 → L2 → L3 顺序点开模块页。每页都有“在系统里的位置”与“相邻模块”。

想看判据

直接去 MOD-07（C0–C5 门禁）与 MOD-08（基线 / 配对 / 坍缩 / test 终检）。

想改代码

每页底部给出 PRD 与代码路径。纪律：先改 PRD / Spec，再改代码与用例；判据类改动必须证明“修复前失败”。

这些页面不是 PRD 的镜像。它们是“按当前代码重画的理解路径”：讲结构、画流程、指出现场状态与已知边界。规范文本仍以 Spec 与 PRD 为准。
