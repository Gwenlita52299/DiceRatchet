MOD-07 evolve

RSI 的执行者：把训练证据变成候选补丁，把候选补丁变成测量，再把测量变成一次可审计的裁决。它不允许“先进再修”，任何不确定都退化为拒绝。

L2 进化 ✅ 已落地 C0–C5 门禁 accept / reject / rollback

01一个候选的一生

先便宜地拒绝，再花钱地接受。判断“补丁是否真的进入 prompt”在评估之前完成（F66）；冒烟只做 triage；真正的证据只有 held-out。

02C0–C5：六道门

accept 的语义不是“显著变强”。它是“打法确实变了，且没有判定出的退化”。这个措辞是刻意的：n=40 的赢率只能判 ≥15pp，把 accept 说成“变强”会过度承诺。
C5 的 tol 是起点值，不是标定值。illegal/fallback 是步级（tol ≈ 上千个事件），truncation 是局级（tol ≈ 2 局）——三轴不可互换。“用实测抖动标定 tol”这件事仍未做。

03play 面指纹：什么算“打法”

play_hash = sha256(
  prompts/decision.md  +  config.json  +  tools/*.py
)   # 不含 reflection.md / dead_ends.md（学习侧，不是打法）

跨代继承

起点 held-out 可按 harness_play_hash 复用——同 play 面已有测量即 0 局，不重测。每 cycle 从 114 局降到 74 局。

判据 1 的同起点豁免

相邻两代 play 面相同 ⇒ 记 not_applicable，不计入可比对；“不降”在两个逐字节相同的起点之间是恒真命题。

F66 的第二半

候选声明改了 play 面文件、实测 play_hash 却没变 ⇒ E_EVOLVE_PATCH_INVALID，花钱之前拒绝。

04版本：accept 建快照，reject 只留死路

D2=A 的代价与收益。拒绝也推进指针，是为了让“这一代被拒绝过”可追溯；代价是版本号不再等价于 play 面，这也是 D-M3-7 改用 play_hash 的原因。

05起点守卫与账本边界

守卫做什么：assert_start_play_plane_accepted() 在 loop run 起跑前检查起点 play_hash 必须是原始 v0（harness/BASELINE.json）或任一已接受快照；否则 E_EVOLVE_UNGATED_START（退出码 2），零推理调用。
守卫不做什么：不追溯否定已经记在账本里的版本；不替代门禁；不拦 loop baseline（测量候选是它的合法用途）。m3r2 的 v1 是 provisional 这一事实，只能靠账本修复，不能靠守卫。
错误码触发处置
E_EVOLVE_PATCH_INVALIDdiff 不合法 / 不可达 / 声明改了 play 面却没变候选 reject，0 局
E_EVOLVE_SCAN_FAILED受限执行扫描失败候选 reject，整批拒绝
E_EVOLVE_LOAD_FAILED工具 worker 起不来候选 reject，0 局（发生在 accept/评估之前）
E_EVOLVE_NO_GAIN / ILLEGAL_RATEC1/C2 或 C5 失败reject，保留 parent
E_EVOLVE_VERSION_CONFLICT版本号冲突 / 指针不一致中止 accept，人工介入，不自动 merge
E_EVOLVE_GIT_FAILEDgit commit/tag 失败decision="error_reject"，version.json 不变
E_EVOLVE_UNGATED_START起点 play 面未裁决起跑前拒绝（退出码 2），0 局
