测量的唯一出口。它只读轨迹与报告、不参与决策；存在的理由只有一个：让“自我改进是否真的发生”成为可复现、可审计、可证伪的数字，而不是模型自评。

01seed 协议：三个世界，永不相交

六位端口不是随便选的。四位 seed 会和耗时（2072.8）、token 预算（2048）、年份（2026）撞车，导致“数字串相等即泄漏”不健全。换成六位后，死名单整删，扫描面反而更严。

02一次测量如何落盘

报告是判据的唯一权威。eval report 重算不得覆盖 report.json 的判决；版本列以报告为准，不一致时发 eval.ledger_version_conflict 并打印 before/after。

03判据 1：held-out 不降，且真的接受过

条件口径
可比对相邻两代 held-out；相邻两代 play_hash 相同 ⇒ not_applicable（不计入可比对）
逐对通过ci_lo(g) ≥ win_rate(g−1) − 0.02 或 P(gap>0) ≥ 0.90
接受记录以各代 report.json 的 decision 为准；≥1 次 accept，否则“全拒”也算单调不降（退化通过）
判定器eval acceptance → metrics/acceptance.json；总是退出码 0（判定器不是守卫）
样本资格--hitl=false 的 auto 决策，若 condition_trace 完整则计入；报告必须写“本轮无人工确认”
诚实边界：winner's curse。上一代被 accept ⇒ 本代起点就是“被选择后的测量”，本身偏高。判据只能给 baseline_selection.selected 标注，不能假装它是无偏基线；不重测、不换篮子。

04判据 2：4–5pp 的量级靠连续指标

为什么不用统计门决定 accept。C2 原先要求“显著提升”，但 n=40 上等效门槛是 +15pp，实测效应只有 +2.5–7.5pp ⇒ 是门没有功效，不是候选不够好。现在 C2 改判“play 面确实变了”，统计量降级为报告项。

05坍缩检测：C1–C4

C1 熵斜率

局内动作熵的斜率过低 ⇒ 决策越来越机械。需连续 confirm_generations 代触发。

C2 动作种类比例

高频 kind 占比过高 ⇒ 策略退化为单一打法。需连续确认。

C3 分布冻结

跨代 kind 分布 JSD 过低 ⇒ 看起来在演化、其实没变。单代即触发。

C4 序列重复

相同动作序列比例过高 ⇒ 复读。也单代即触发。

坍缩是“否决”，不是“拒绝”。collapse_flag=true 时禁止 real_gain，但报告仍保留完整指标；它不负责决定 accept/reject，那个权力在 MOD-07。
