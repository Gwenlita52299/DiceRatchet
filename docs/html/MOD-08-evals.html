MOD-08 · evals

评估度量层：把「自我改进」变成可复现、可审计、可证伪的数字

GameRSI 的 L3 测量层。它只读轨迹与报告，不参与任何决策——接不接受一个候选，由 MOD-07 的 gate 说了算；MOD-08 只负责把「这一代真的变强了吗」算成一个经得起复核的数字。

版本 v0.3 状态：待评审 里程碑：M1 基线 → M2 执行器/指标 → M3 完整 落地：gamer_rsi/evals/*.py
背景与目标
「自我改进是否真的发生」不能靠模型自评。MOD-08 让这个判断成为可复现、可审计、可证伪的数字：主指标只用环境原生结果，shaped reward 绝不进入判定路径。
核心职责
seed 协议与三重隔离护栏、评估执行器、INV-7 指标体系、增益真实性裁决（verdict）、多样性/坍缩检测、消融归因、基线归档与报告落地。
服务对象
MOD-07 evolve/judge（每候选在 H1 上取 verdict）、MOD-06 loop（代际报告入口）、MOD-09 infra/CLI 与绘图、以及复核增益真实性的人。
关键成功度量
同参数重跑 report.sha256 逐字节一致（G3）；audit leak 0 告警、蜜罐必被抓（G4）；verdict 只信环境原生结果，坍缩时一票否决 real_gain。

1背景与目标

MOD-08 是整个系统的测量层，唯一理由是回答一个危险的问题：「自我改进是不是真的发生了？」如果这个答案由模型自己给（自评），项目就没有证据。所以 MOD-08 的设计全部围绕「怎么让数字不可作弊」展开：

  • G-1 可信主指标：主指标只用环境原生结果（INV-7 白名单），shaped reward 不得进入任何判定路径。
  • G-2 防自证：held-out 与训练局严格隔离（INV-5），verdict 明确区分 real_gain 与 overfit_suspect。
  • G-3 防坍缩：动作熵曲线 + 跨代分布 JS 散度产出 collapse_flag，对齐调研失败模式 2（多样性/模型坍缩）。
  • G-4 可归因：消融（去反思 / 去自编辑）回答「增益来自哪条机制」。
  • G-5 可复现：同 (run_id, generation, split, seeds) 重跑得到逐字节相同的 report.json。

2范围：负责什么、不负责什么

MOD-08 的边界很干净：只出数字与 verdict，不出决策。下面两栏对照来自 Spec §3 的「负责 / 不负责」清单。

✓ 范围内
  • configs/seeds.yaml 的协议部分：seed 区间、篮子、exposure 策略、hash 固化与 CI 校验规则；三类 seed 隔离的代码级护栏（INV-5）。文件加载归 MOD-09。
  • 评估执行器：harness_version + seed 列表 + 预算 → 并行跑局并汇总；基线 random / heuristic / fixed_prompt 的实现、与 MOD-04 的复用关系、不可变归档。
  • 指标（Spec v1.3 INV-7）：win_rate + Wilson 95% CI、mean_stages_cleared、mean_hearts_left、mean_battles_won、mean_decisions、illegal_rate、fallback_rate、truncation_rate、归一化动作熵与每决策点的熵曲线。
  • shaped reward 定义（evals/reward.py，只供学习与调试，由 MOD-01 移交）。
  • 增益真实性（win_rate_gap + verdict）、多样性/坍缩（entropy_slope、js_divergence、collapse_flag）、消融两变体。
  • 报告落地：report.json、metrics/generations.csv、绘图 tidy 数据（绘图本身归 MOD-09）。
✗ 范围外
  • 不负责修改 harness（MOD-07）——MOD-08 只出数字与 verdict，接受/拒绝/回滚由 MOD-07 gate.py 决定。
  • 不负责写游戏规则（MOD-01）——胜负、HP、击杀、楼层由 info 原生给出，MOD-08 不做规则解释或二次判定。
  • 不负责编排训练局（MOD-06）——train seed 的消耗顺序由 MOD-06 驱动，MOD-08 只登记与统计。

4功能需求

每条 FR 都可单独测试。下面按「seed 协议 → 执行器 → 指标 → 裁决 → 报告」的顺序讲一遍。

seed 协议与隔离护栏

  • FR-08-01加载 seeds.yaml 并校验三类区间两两不相交；任一重叠抛 E_EVAL_SEED_OVERLAP。
  • FR-08-02train（默认 1000–1999）按 per_generation=30 顺序切块：第 g 代用 1000+30(g-1) … 1029+30(g-1)；越界抛 E_EVAL_SEED_EXHAUSTED。
  • FR-08-03heldout（2000–2099）切成固定篮子：H1=2000–2039（代际裁判）、H2=2040–2079（消融/终检复核）、H3=2080–2099（应急）；篮子成员不得重新抽样。
  • FR-08-04test（9000–9099）默认锁定；仅 test_unlock 解锁，每里程碑 ≤1 次，落 test_attestation.json；结果不得进入代际决策路径。test 同时跑两种局：默认局（主结论）和完整局 medium × 10 关（次级「迁移」指标，Spec §8.6，只报告不判定）。
  • FR-08-05/06guard_prompt_context() 在 prompt/memory/reflection 三个 destination 上断言文本不含 heldout/test seed 数值 token；split != "train" 的局任何 memory 写入与 reflection 落库被拦截；两者命中均抛 E_EVAL_INV5_LEAK。

评估执行器

  • FR-08-07/08/09/10run_eval() 支持 n_workers≥1，结果按 seed 升序归一化聚合且与串行逐字节一致；评估 temperature=0.0（训练沿用 ≥0.7）；每 seed 默认 1 局（后端非确定时 n_rep=3 多数票）；超时或崩溃的局记为 dropped，计入 n 并按 lose 计（Spec v1.3 §8.5，防止幸存者偏差），另外单列 n_dropped；dropped/n > 0.10 时抛 E_EVAL_INSUFFICIENT_N 并标 low_confidence=true。degraded 局（模型不可用、由启发式代打）则从 n 中剔除，单列 degraded_n。
  • FR-08-11/12三基线可用同一 EvalSpec 跑通并归档；归档不可覆盖：同名时写 <kind>-<split>-<ts>.json 并向 registry.csv 追加一行。
  • FR-08-13/14heuristic 复用 MOD-04 agent.heuristic.heuristic_policy()（Spec §4.7，禁止复制第二份启发式逻辑；它移植自 GAME greedy_counter，默认局上的参考通关率为 45.5%（n=200，seed 1–200））；fixed_prompt 固定 harness_version=0、memory_enabled=false、reflection_enabled=false。

指标与报告

  • FR-08-15/16计算 win_rate / wilson_ci() / mean_stages_cleared / mean_hearts_left / mean_battles_won / mean_decisions / illegal_rate / fallback_rate / truncation_rate，全部由整数累加器聚合后单次相除。action_entropy_curve 以决策点序号为横轴，长度 T_max（默认 120），样本数 < min_support 的位置写 null。截断局的 outcome 一律记为 lose。
  • FR-08-17生成 report.json 并通过 additionalProperties=false schema 校验；扩展指标写入 metrics/gen-XXX.ext.json。
  • FR-08-18计算 win_rate_gap = train.win_rate - heldout.win_rate，按 §8.2 有序规则产出 verdict。
  • FR-08-19按 §8.3 的 OR 条件 + 两点确认产出 collapse_flag；为真时禁止 real_gain（collapse_veto）。
  • FR-08-20/21计算跨代 js_divergence，两个口径：action.kind，以及 play_face 的 slotKind×school；run_ablation() 在 H2 上跑 3 臂（full / no_reflection / no_self_edit）并做配对检验，产出 attribution ∈ {reflection, self_edit, both, none}。
  • FR-08-22生成 metrics/generations.csv（每代追加一行）与 metrics/plots_data/gen-XXX_entropy.json。
  • FR-08-23/24主指标聚合路径结构上不可读取 reward / cum_reward（INV-7）：EpisodeResult 不含这两个字段；报告落盘后写 report.sha256，同参数重跑必须一致，否则抛 E_EVAL_NONDETERMINISTIC。

MOD-07 门面（统计检验的唯一出口）

  • FR-08-25（Spec §4.7）提供三个门面函数：evaluate_arm()、compare_paired()（胜率用 McNemar 精确检验，连续量用配对 bootstrap B=10000）、evaluate_generation()（只返回 report 的指标段，MOD-07 负责合并，MOD-09 原子写入）。MOD-07 不得自行实现统计检验。

5非功能需求

  • NFR-08-01确定性：所有随机性来自显式 seed。bootstrap 用 np.random.default_rng(rng_seed)，rng_seed = int.from_bytes(sha256(f"{run_id}:{generation}:{basket}".encode()).digest()[:8])；禁 random.*（MOD-09 guards.py AST 扫描）。环境部分由 seed 完全决定，模型部分在 temperature=0 下尽力确定；后端不保证时必须显式降级（E_EVAL_NONDETERMINISTIC 告警 + n_rep=3），不得静默。
  • NFR-08-02统计严谨：任何「提升」结论必须给点估计 + 区间 + 检验；配对比较用 McNemar，次级指标用 BH-FDR(q=0.10)，消融用 Holm–Bonferroni。
  • NFR-08-03可复现：config_hash / harness_version / seeds_hash / bootstrap_seed 全部写入报告；§12 的命令可直接复制执行。
  • NFR-08-04可观测：每次评估 ≥1 行 eval_index.jsonl；埋点走 MOD-09 结构化日志，禁止自建日志格式（Spec §8.2）。
  • NFR-08-05成本：由 Spec v1.3 §8.6 成本模型推出——单局 ≈ D·t_d ≈ 5 min（默认局，8B），所以 n=40 的 heldout 评估 ≈ 3.3 h。局级并发共享同一推理队列（P-10），并发数不能缩短推理瓶颈，只能掩盖 env/IO 开销。报告必须写实测 dur_s，不设不可达的 wall-clock 目标。

8关键流程

8.1 代际评估主流程

一次代际评估的骨架：取 seed → 隔离校验 → 并行跑局 → 聚合 → 裁决 → 渲染报告段。

evaluate_generation(g, harness_version, split, basket):
  seeds = resolve_basket(basket, generation=g, protocol=load_seeds())   # load_seeds 由 MOD-09 提供
  assert_split_isolation(split, seeds)                                  # FR-08-01/05
  spec = EvalSpec(run_id, g, harness_version, split, basket, seeds, ...)
  with EpisodePool(n_workers, shared_client) as ex:   # 局级并发 + 共享推理队列（P-10），按 seed 排序收集
      for seed in seeds: ex.submit(play_one, seed, spec)
  heldout = aggregate(sorted(results, key=lambda r: r.seed))            # 整数累加后单次相除
  train   = aggregate(train_window(g))                                  # 滚动窗口，默认 60 局
  gain = judge_gain(train, heldout, parent_metrics, rng)                # §8.2
  div  = collapse_check(curves_by_gen, jsd_series, win_rates, cfg)      # §8.3
  sections = render_report_sections(...)   # 交给 MOD-07 合并 decision 段，MOD-09 write_json_atomic + sha256

8.2 verdict 有序规则（短路求值）

verdict 不是「赢了就是 real_gain」，而是一条有序短路的规则链。顺序很关键：先排除回退，再排除过拟合，最后才看是否真增益。

gap = train.win_rate - heldout.win_rate
p_improve = mcnemar_exact_p(cand, parent, "greater")   # 配对：cand 与 parent 跑同一 H1 篮子
p_regress = mcnemar_exact_p(cand, parent, "less")
if p_regress < alpha:                                       verdict = "regress"
elif gap > cfg.gap_threshold:                               verdict = "overfit_suspect"
elif p_improve < alpha and gap <= threshold and not collapse_flag:  verdict = "real_gain"
elif collapse_flag:                                         verdict = "null"; collapse_veto = True
else:                                                       verdict = "null"
n=40 的现实约束（必须写入报告 power_note）：配对 McNemar 精确检验在 n=40 下最小可判显著的不一致对数 k=6（k=6 双尾 p=0.031，k=5 p=0.0625）。故 verdict 实际由 gap 主导、显著性为辅——「未判 real_gain」不等于「无提升」，只是证据不足。

8.3 collapse_flag 触发条件

四个条件对齐调研 §4 失败模式 2。C4 是最直接的坍缩表征（轨迹高度重复），单独即可触发；C1/C2/C3 需要连续 2 代触发才算（两点确认，避免单代噪声）。

#条件默认阈值含义
C1entropy_slope <= -0.010-0.010动作分布随回合快速收敛
C2entropy_mean_norm(g) < 0.60 × entropy_mean_norm(gen_0)0.60相对首代多样性退火
C3jsd_kind(g,g-1) < 0.010 且 win_rate 提升 ≥0.05 且连续 2 代0.010行为分布冻结但分数上涨 → 疑似刷分 / 自我确认
C4distinct_sequence_ratio < 0.500.50轨迹高度重复（坍缩最直接表征）

collapse_flag = C4 OR (C1/C2/C3 任一在连续 2 代触发)；collapse_reasons 记录被触发的条件 ID。

8.4 消融与归因

消融回答「增益来自哪条机制」。三臂跑同一批 40 seed（配对），臂内并行、臂间串行。

run_ablation(g, arms=[full,no_reflection,no_self_edit], split_basket="H2"):   # 同一批 40 seed，配对
  no_reflection: 禁用 MOD-06 反思触发 + MOD-05 反思条目检索注入（策略记忆保留）
  no_self_edit : harness 冻结于 v0（prompts/tools 只读），反思与记忆演化保留
  full         : 当前 harness_version；三臂同 seed 同预算，臂内并行、臂间串行
  delta_full[arm] = full.win_rate - arm.win_rate
  attribution = {reflection|self_edit|both|none}   # 由 Holm–Bonferroni(α=0.025) 下显著项决定

10错误处理与降级

错误码统一用 Spec §8 的 E_EVAL_* 前缀。核心原则：宁可保守报 null，也不输出虚假的 real_gain。

错误码触发严重度降级行为
E_EVAL_INV5_LEAKprompt/memory/reflection 含 heldout/test seed，或非 train 局写记忆P0立即终止该局标 dropped；整代评估作废并要人工复核；禁出 real_gain
E_EVAL_SEED_OVERLAPE_EVAL_TEST_LOCKED三类区间相交 / 未解锁即跑 testP0 / P1拒绝启动（必须修 yaml）；test 直接拒绝执行
E_EVAL_SEED_EXHAUSTEDtrain 切块越界P1停止演化，提示扩大 train 池或降低 K
E_EVAL_INSUFFICIENT_NE_EVAL_BUDGET_EXCEEDED有效 n 不足、dropped/n > drop_rate_max、软预算耗尽P1 / P2出报告但 low_confidence=true，verdict 只能为 null / regress（保守，对齐 Spec §8.5）
E_EVAL_NONDETERMINISTIC重跑 sha256 不一致P2转 n_rep=3 多数票；报告标注，禁 real_gain
E_EVAL_SCHEMAreport.json 校验失败P1不写正式路径，保留 .invalid.json 供排查（不得静默丢弃）
E_EVAL_BASELINE_MISSINGE_EVAL_ARM_NOT_ALLOWED--baseline all 但归档缺失 / 请求未知消融臂P2报告 baselines: null 并标注对照缺失；拒绝该臂，其余继续

11测试计划

单测

  • T-01 Wilson CI 手算：给定 wins=3, n=5（p̂=0.6）→ wilson_ci(3,5) → 返回 (0.2307, 0.8824)（z²=3.841459；中心 0.556523，半宽 0.325828），容差 1e-4；边界 wins=0,n=40 → ≈(0.0000, 0.0876)；n=0 → 抛 E_EVAL_INSUFFICIENT_N。
