MOD-04 policy

观测到动作之间的唯一翻译层。它负责三件事：把允许的信息组装成可复现的 prompt、把模型文本校验成合法动作、在失败时退化为可解释的启发式——而不是让一次坏输出污染整局指标。

L1 智能体 ✅ 已落地 INV-3 唯一执行者 三级校验 + R=2 重试

01prompt 只允许四个来源

INV-3 规定：进入 prompt 的文本只允许来自 ① 当前投影观测 ② MOD-05 检索到的记忆 ③ 当前 harness 工件 ④ 冻结的任务说明。assemble_prompt() 是唯一注入出口，调用方不得自行拼接。

压缩只影响“模型看得到什么”。语义校验仍以全量 legal_actions() 为准；forge 阶段的合法动作可达 690 条，必须压缩渲染。
为什么把哈希写进轨迹。prompt_hash 让「候选补丁是否真的进入了 prompt」变成可对拍的事实——F66 就是靠它发现候选臂与 parent 的首个决策点哈希逐字节相同（40/40）。

02一次决策：计划、校验、重试、fallback

失败是数据，不是崩溃。每次失败都记一次 attempt、一次轻罚和一份错误详情；最终 fallback 也只是“本决策降级”，是否判负由 MOD-02 统一决定。
模板细节不是文案问题。实测给真实 8B 补上「可选字段直接省略」后，首答 schema 通过率 71% → 92%；补上「一次决策 = 一个回合」后，每决策点合法动作数 1.35 → 2.32。两条模板（演化版与冻结基线版）必须对称保留这些规则，否则基线与 agent 的强度不可比。

03启发式不是备胎，是对照组

heuristic_policy() 逐行移植 GAME 的 greedy_counter。它同时承担两个角色：模型失败时的 fallback，以及 MOD-08 的免费基线。参考通关率：默认局 45.5%（JS，n=200，seed 1–200），Python 版须在 ±3pp 内。

05F66：候选补丁“从未进入 prompt”

现场：M3 正式实验里，候选臂与 parent 在同 40 个 seed 上的首个决策点 prompt_hash 逐字节相同（40/40）。若候选模板真的含那 6 行补丁，交集必须为 0。根因是 evaluate_arm 在注入 runner 时把 harness_dir 架空了；staging 目录进了归档 provenance，却从未到达 PolicyAgent。

修法

让 runner 感知 per-arm harness_dir；解析先看该臂目录，再回落 CWD；候选臂的解析落点必须在该臂目录内，否则 E_EVOLVE_PATCH_INVALID，不花钱。

护栏

臂归档记实际加载的 template_hash；MOD-07 断言「有 prompt_patch 的候选其 template_hash ≠ parent」，fail-closed。

影响

M2 冒烟与 M3 彩排的候选结论一并待复核。“0 accept”不等于“补丁无效”，可能只是“补丁从未被测试”。
