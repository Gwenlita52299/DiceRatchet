MOD-01 · env-rules

环境规则内核 —— GAME 内核的纯 Python 等价移植

把已验收的 JS 游戏内核逐位搬进 Python，让智能体侧在进程内直接调用游戏， eliminating 进程边界与网络延迟，并让确定性审计不再依赖网络栈。

版本 v1.0 状态：待评审 所属里程碑：M0 2026-09-30 17:21 按 Spec v1.3 重写
背景与目标
智能体侧（MOD-02～08）全是 Python，而游戏本体是 JS。训练若经 HTTP 调 JS 会引入进程边界、延迟，并让确定性审计依赖网络栈——所以需要一份进程内、逐位等价的 Python 内核。
核心职责
与 src/game/kernel/*.js 一一对应的 Python 模块，加对外门面 GameEngine。只移植规则，不发明、不修改规则。
服务对象
MOD-02 构造 SandboxEnv（agent 的唯一入口）、MOD-04 启发式 fallback、MOD-08 基线评估，以及开发者 / CI 的对拍自检。

5 组 golden（约 1,470 步）逐行对拍 100% 通过；200 局随机差分对拍 0 分歧；greedy_counter 通关率与 JS 相差 ≤ 3pp；性能达 §5 要求。

1背景与目标

GameRSI 的智能体侧（MOD-02～08）全部用 Python，而游戏本体已经用 JS 实现并验收（src/game，零依赖）。训练若经 HTTP 调用 JS，会引入进程边界和延迟，也会让确定性审计依赖网络栈——因此需要一份供 SandboxEnv 在进程内调用的 Python 内核。

唯一目标：给定同一份配表、同一个 config 和同一个动作序列，Python 内核每一步的 obsDigest、rngDigest、stateDigest 都与 JS 内核逐字节相等。

这句话是整个模块的北极星：所有 FR、NFR、测试、验收标准，全都在为「逐字节相等」服务。

成功度量

  • ① src/game/tests/golden/*.jsonl 5 组共约 1,470 步逐行对拍 100% 通过。
  • ② 额外 200 局随机动作的差分对拍（JS 与 Python 各跑一遍）0 分歧。
  • ③ Python 版 greedy_counter 在默认局（hard × 6 关，n=200）上的通关率与 JS 相差 ≤ 3pp。
  • ④ 性能达到 §5 的要求。

2范围

一句话记住边界：本模块只搬运规则，不定义规则。规则、数值、配表一律引用 GAME。

✓ 负责
  • 与 src/game/kernel/*.js 一一对应的 Python 模块：rng/digest/loader/state/slots/counter/risk/relic/combat/map/shop/forge/event/index。
  • 对外门面 GameEngine（Spec §4.7 第 1 行）。
  • 配表加载：直接读取 src/game/content/*.json，校验规则同 GAME-01 §8。
  • 错误码映射：E_KERNEL_*/E_CONTENT_* → E_ENV_*，E_ACTION_* 原样保留。
  • 对拍工具：golden 重放 + JS/Python 差分对拍脚本。
  • heuristic 所需的只读辅助：legal_actions、play_hints（供 MOD-04 移植 greedy_counter）。
✗ 不负责
  • 发明或修改规则——规则改动先改 GAME PRD 与 JS 内核，再同步移植。
  • 观测裁剪（MOD-02）、prompt（MOD-04）、模型调用（MOD-03）、shaped reward 与评分统计（MOD-08）。
  • 写文件、发日志（归 MOD-09）。
  • 实现 SandboxEnv、reject()、policy_failure 判负（归 MOD-02）。
  • 生成 golden——golden 只能由 JS scripts/golden-gen.js 生成，Python 侧只读。
  • Web 会话挂起逻辑（GAME consecutiveIllegal 字段照常移植以保持 stateDigest 一致，但 agent 路径不据此判定）。

3使用方与场景

典型用法是「套一层 MOD-02」：除开发者命令外，所有使用方都经 SandboxEnv 触达本模块，不直接实例化 GameEngine。

使用方调用场景
MOD-02GameEngine.create/reduce/legal_actions/observe/digest构造 SandboxEnv；agent 只能经 MOD-02 触达
MOD-04GameEngine.play_hints（经 MOD-02 SandboxEnv.hints() 转发）启发式 fallback
MOD-08经 MOD-02 调用基线、评估
开发者 / CIpython -m gamer_rsi env selftest、pytest tests/golden对拍

4功能需求

共 12 条 FR。核心线索：先保证「算法等价」（FR-01-2/3/4），再保证「结构等价」（FR-01-1/5/8/9），最后是「协作契约」（FR-01-6/7/10/11/12）。

  • FR-01-1模块一一对应：每个 JS 文件对应一个同名 Python 文件（index.js → engine.py），函数名改 snake_case，但参数与返回的 dict 键保持 camelCase 不变——与 GAME 状态、观测、动作逐字相同，stateDigest 才能直接对拍。
  • FR-01-2随机：逐位移植 rng.js。xmur3(streamName) 与 rootSeed 混合 → SplitMix64，64 位运算用 16 位分片（GAME-01 §7 P-5）；STREAM_NAMES 与 JS 完全一致：dice.enemy, dice.player, event, forge, levelup, loot, map, shop；randint 用拒绝采样，shuffle 为 Fisher–Yates；禁止 random、hashlib 参与派生（sha256 只用于 digest）。
  • FR-01-3规范化与摘要：stable_stringify 行为与 JS stableStringify 完全相同——递归排序键、ensure_ascii=True、separators=(",",":")、禁止 float；digest(v) = "sha256:" + sha256(stable_stringify(v))。
  • FR-01-4整数算术：全面遵守 GAME-01 §7 P-1～P-14。禁止 / 和 int() 截断，Math.floor(x/y) 一律写成 x // y（除数恒为正）；位运算后 & 0xFFFFFFFF；千分倍率与 JS applyMul 同式。
  • FR-01-5配置：apply_difficulty(base, difficulty, tables) 与 JS 同名函数输出相同的 dict，包括 D-34 stageCount ∈ allowed_stage_counts(tables)；validate_config 返回相同的错误键列表。
  • FR-01-6reduce：reduce(state, action, tables) -> {"state", "events", "illegal", "code", "reason", "error"}。语义同 GAME-01 §4：不合法时返回原 state 与 illegal=True，不抛异常；内核异常时 error={"code","message"}，state 不变；end_turn 在同一次 reduce 内按 §4.2 的 E0～E12 顺序跑完整个敌方回合。
  • FR-01-7写时构造：不原地修改入参 state（GAME-01 P-14）。先 copy.deepcopy 再修改；性能不足时改为结构共享，但对外语义不变。
  • FR-01-8legal_actions：与 JS legalActions 的元素与顺序完全一致（MOD-02 据此去掉 abandon_run）。
  • FR-01-9observe：实现 view ∈ {"full","visual"}，输出与 JS observe 相同，含 stats、legalActionKinds、seed:null。
  • FR-01-10错误码映射：见下表（映射表在 MOD-09 errors.py 登记）。
  • FR-01-11原生结果：native_result(state) -> {"outcome", "truncationReason", "stagesCleared", "heartsLeft", "battlesWon", "turns", "kills"}，供 MOD-02 填写 StepResult.info（INV-7）。
  • FR-01-12版本：KERNEL_VERSION = "kernel-1.0.0"、OBS_SCHEMA = "obs-1.0.0"，与 JS 同值；JS 升版时 Python 必须同步升版，CI 比对两侧常量。

5非功能需求

  • NFR-01-1确定性：结果与 PYTHONHASHSEED、TZ、locale、平台无关；CI 在 PYTHONHASHSEED ∈ {0,12345} × TZ ∈ {UTC, Asia/Tokyo} 下各跑一次 golden。
  • NFR-01-2性能（Python 3.11，M 系列）：reduce p95 ≤ 2 ms（JS 实测 0.163 ms，按约 10× 的解释器差距估算）；默认局整局 bot 自玩 ≤ 1.5 s；observe p95 ≤ 1 ms——相对单个 LLM 决策（约 3 s）可以忽略不计。
  • NFR-01-3零依赖：只用标准库。
  • NFR-01-4隔离：不 import gamer_rsi 的其他子包（除 infra.errors），由 MOD-09 guards 强制。

6接口契约

所有使用方都通过 GameEngine 这个门面与内核打交道。注意 dict 键保持 camelCase——这是跨语言对拍的硬约束。

# gamer_rsi/env/engine.py
KERNEL_VERSION: Final = "kernel-1.0.0"
OBS_SCHEMA: Final = "obs-1.0.0"
ACTION_KINDS: Final[tuple[str, ...]]      # 同 JS ACTION_KINDS（17 个，含 abandon_run）
TOGGLE_KEYS: Final[tuple[str, ...]]

class GameEngine:
    def __init__(self, tables: Tables) -> None: ...
    def create(self, config_input: Mapping[str, Any]) -> GameState: ...          # = createGame
    def reduce(self, state: GameState, action: Mapping[str, Any]) -> ReduceResult: ...
    def legal_actions(self, state: GameState) -> list[dict]: ...
    def is_legal(self, state: GameState, action: Mapping[str, Any]) -> LegalCheck: ...
    def observe(self, state: GameState, view: Literal["full", "visual"] = "full") -> dict: ...
    def play_hints(self, state: GameState) -> dict: ...
    def native_result(self, state: GameState) -> NativeResult: ...
    def replay(self, config: Mapping[str, Any], actions: Sequence[Mapping]) -> ReplayResult: ...

def apply_difficulty(base: Mapping, difficulty: str, tables: Tables) -> dict: ...
def allowed_stage_counts(tables: Tables) -> list[int]: ...                    # [3, 6, 10]
def digest(value: Any) -> str: ...                                            # "sha256:<64hex>"
def state_hash(state: GameState) -> str: ...                                  # = digest(state)

# gamer_rsi/env/loader.py
def load_tables(content_dir: Path = GAME_CONTENT_DIR) -> Tables: ...
GAME_CONTENT_DIR: Final = Path("src/game/content")                            # 可由 GAMERSI_ENV__CONTENT_DIR 覆盖

GameState = dict[str, Any]         # 结构同 GAME-01 §2 GameState（camelCase 键）
Tables = Mapping[str, Any]         # 只读；load_tables 返回深度冻结视图

ReduceResult、NativeResult 为 TypedDict，键名同 JS。

7数据模型与存储

  • 不自建数据模型：GameState、Observation、Action 的结构全部由 GAME-01 §2/§5 与 GAME-00 §9.4 定义。Python 侧用 TypedDict 做类型提示（gamer_rsi/env/types.py），由 GAME-01 生成。
  • 配表：只读 src/game/content/*.json，不复制、不转换。content_hash = digest(tables) 记入 config.json（MOD-09）。
  • 持久化：本模块不写盘；续跑所需的状态快照就是 GameState dict 本身（可 JSON 序列化），由 MOD-06 保存。

10错误处理与降级

错误码触发处理
E_ENV_CONTENT_INVALID配表校验失败启动即失败，退出码 2
E_ENV_CONFIG_INVALIDapply_difficulty/validate_config 失败抛出，由调用方退出码 2
E_ENV_INTERNAL不变式违反或分派异常reduce 返回 error，state 不变；MOD-02 将该局标为 degraded
E_ENV_RNG未注册流名或 randint 区间非法同上
E_ENV_PARITY_MISMATCH对拍不一致（仅测试/自检）CI 失败，退出码 1
E_ACTION_*非法动作正常返回 illegal=True，不是错误
不降级：内核错误说明 Python 与 JS 的等价性被破坏，禁止用「跳过该步」之类的方式掩盖。

12验收标准

  • G1：gamer_rsi/env/ 行覆盖 ≥ 90%（JS 侧为 95.8%）。
  • G2：T-04 全部通过；golden 只读，禁止 Python 侧生成替代快照。
  • G3：T-08 通过。

  • M0：T-04/T-05/T-09 通过，并与 MOD-02 SandboxEnv 联调完成一局默认局。

16开放问题

  1. GAME-01 P-5 要求 Python 也用 16 位分片做 64 位乘法。Python 原生大整数加掩码的结果与之相同且更快，是否放宽为「算法任选，测试向量必须通过」？（建议放宽，需修订 GAME-01。）
  2. 差分对拍需要 JS 侧新增 --random-walk 模式（scripts/golden-gen.js），以及 --dump-state 调试导出。归 GAME 侧，工作量约 0.3 人日。
  3. 如果将来需要多进程并行跑环境，Tables 的冻结视图是否要支持 pickle？
