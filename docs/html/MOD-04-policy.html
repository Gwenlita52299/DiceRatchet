MOD-04 · policy

决策策略层：把观测变成 prompt，把 LLM 废话变成合法动作

1背景与目标

M1 的交付物是「8B agent + 三基线」，而计划 §8 已经点名了最大的风险：LLM 输出非 JSON / 非法动作多。MOD-04 是这个风险的唯一收口处——它把 Observation 变成 prompt，把 LLM 的原始文本变成 Action，并且要保证模型再离谱也不污染环境与指标。

四个目标

  • 组装可复现：给定 obs + memory + harness_version + seed，prompt 逐字节确定，并记录 prompt_hash。
  • 输出可收敛：三级校验 + 每步 R=2 重试 + 轻罚 -0.05 + 连续 3 次非法判负，非法率可度量。
  • 演化面可控：MOD-07 只能通过 harness/prompts/decision.md、harness/tools/*.py、harness/config.json 影响决策；MOD-04 自身代码不在演化面内。
  • 永不空转：模型不可用、重试耗尽、工具异常、泄漏告警四类故障，都退化为可解释的启发式动作。
成功度量：held-out 上 illegal_rate ≤ 0.02、E_ACTION_PARSE 占比 ≤ 0.01、fallback_rate ≤ 0.05、同 seed 重跑 prompt_hash 与动作序列逐字节一致。
判据范围（2026-10-06，M1 验收复核裁定）：illegal_rate / fallback_rate 刻画的是最终演化后的 harness agent（harness/prompts/decision.md + 工具/记忆/反思全开），由 M3 在 held-out 上判定；M1 不做该达标判断（M1 用 full PolicyAgent 实跑得到的是基线数据，不是被考核对象）。历史注记（勿再引用）：M1 验收报告 §1 早期「illegal_rate=0.0 达标」依据的是 F1 修复前静默降级为启发式的假 fixed_prompt 归档（启发式非法率构造性为 0），已被基线实测 0.3021 / 0.181 取代。详见 M1 验收复核 §M-2。

2范围

搞清楚边界，才知道出了问题该找谁。下面左栏是 MOD-04 要背的锅，右栏是别人的锅。

✓ 负责（范围内）
  • prompt 模板加载、占位符填充、上下文预算与裁剪、prompt_hash 计算与记录。
  • INV-3 上下文白名单的唯一注入出口，以及对 MOD-02 泄漏扫描的强制调用。
  • LLM 原始输出 → Action 的解析与三级校验、legal_actions() 语义判定。
  • 非法动作的重试编排、轻罚触发、illegal_rate 记账与连续非法判负。
  • @harness_tool 装饰器、rank_actions() 注册表、受限加载与异常降级。
  • 模型不可用 / 重试耗尽时的启发式 fallback（含 baseline_heuristic 复用）。
  • 探索 / 评估 / 基线三种模式的采样参数覆盖与显式 seed 派生。
  • 决策事件与轨迹字段产出（落盘由 MOD-09 负责）。
✗ 不负责（范围外）
  • 加载模型（MOD-03）。
  • 改自己的 prompt 文件（那是 MOD-07 的写入动作）。
  • 记忆检索实现（MOD-05）。
  • 不实现游戏规则与奖励计算（MOD-01）。
  • 不做非法动作判定的权威裁决（MOD-01 判、MOD-02 记账）。
  • 不定指标口径（MOD-08）。
  • 不自建日志格式、不写 runs/ 目录结构（MOD-09）。
  • 不在代际边界之外读写 harness 工件。

3使用方与场景

MOD-04 在九模块里处于「承上启下」的位置：上接 MOD-06 的主循环，下调 MOD-03 的推理、MOD-02 的沙箱、MOD-05 的记忆。

使用方调用点契约
MOD-06 loop每个决策点 PolicyAgent.play_decision(env, obs, ctx) -> DecisionResult一个决策点（计划 + 重试 + fallback）；不查环境内部状态
MOD-07 evolve代际边界替换 harness/ 三工件后新建 PolicyAgent只读消费；MOD-04 不做热重载
MOD-08 evalsmode="baseline_fixed_prompt" / "baseline_heuristic"冻结模板 fixed_v1.md；启发式不调 LLM
MOD-09 infra配置加载、python -m gamer_rsi play --agent llm配置键见 §9；日志走 MOD-09
MOD-03 inferencegenerate_json(prompt, schema, sampling)MOD-04 只传 prompt / schema / 采样参数

典型场景

  1. 训练局逐步决策；
  2. held-out 评估局（固定采样、固定 seed 组）；
  3. M1 格式鲁棒性专项（喂畸形 llm_raw）；
  4. 模型服务宕机 → 整局退化 heuristic 并显眼标注（该局不计入评估样本）。

4功能需求

共 16 条 FR，每条都可独立测试。新人可以先抓主线：FR-04-1~FR-04-4 管 prompt 组装，FR-04-7~FR-04-10 管决策与重试，FR-04-14 是最后的兜底。

  • FR-04-1模板加载：policy.template_path 必须存在且 UTF-8 可解析，且含 {{observation}}、{{memory}}；缺失 → E_ACTION_TEMPLATE，回退内置 gamer_rsi/agent/prompts/decision_fallback.md 并置 fallback_used=True。
  • FR-04-2填充顺序固定：按 {{task}} → {{harness_version}} → {{tools}} → {{observation}} → {{reflections}} → {{memory}} → {{constraints}} 单遍替换；未知占位符保留原样并记入 PromptBundle.unknown_placeholders。
  • FR-04-3上下文预算与裁剪：预算 policy.prompt_token_budget（默认 3072，按 policy.token_estimator 估算）。优先级「当前 Observation > 近期反思 > 策略记忆 top_k」：{{task}}/{{harness_version}}/{{tools}}/{{observation}} 永不裁剪；反思按 (generation desc, reflection_id asc) 留最多 policy.reflection_max 条；memory 按 (score desc, memory_id asc) 留 top_k 且先丢分数最低者；每次丢弃写入 PromptBundle.truncated。
    补充：{{legal_actions}} 超预算时的压缩（2026-10-05，M1 验收 F13）：实测某 phase=forge 决策点的合法动作是笛卡尔积（23 张骰 × 6 个面 × 5 个候选 = 690 条 forge_pick），完整枚举 54,393 字符 ≈ 19,633 token，而观测本身只有 2,798 字符。裁剪顺序因此扩展为：① 丢 memory → ② 丢 reflections → ③ 把 {{legal_actions}} 换成压缩渲染 → ④ 仍超预算才 E_ACTION_BUDGET（观测段仍永不裁剪）。压缩渲染是确定性的：按 kind 分组列出字段取值集合（每字段最多 8 个，其余记 …(+K)）+ 每种 kind 等距抽 12 条真实合法动作作为可照抄样例，并在 PromptBundle.truncated 记 TruncationRecord("legal_actions", …, "budget")。语义校验仍以全量 legal_actions() 为准（FR-04-8），压缩只影响「模型看得到什么」。
  • FR-04-4prompt 哈希：prompt_hash = "sha256:" + sha256(rendered_text.encode("utf-8")).hexdigest()；同一 obs_digest + harness_version + sorted(memory_ids) + mode 必须得到同一 hash。
  • FR-04-5INV-3 白名单：进入 prompt 的文本只允许四个来源——① 当前 Observation（SandboxEnv.observe() 投影结果）② MOD-05 检索到的 memory 条目 ③ 当前 harness 工件（prompts/decision.md、tools/*.py 签名摘要、version.json）④ 任务说明 gamer_rsi/agent/prompts/task.md。assemble_prompt() 是唯一注入出口，禁止调用方拼接 prompt。
  • FR-04-6强制泄漏扫描：每次 LLM 调用前（含重试的修复 prompt）必须调用 MOD-02 sandbox.audit.scan_text(text, surface="prompt")；有 finding → E_ACTION_LEAK_BLOCK，按 §10 阶梯降级。policy.leak_scan 恒 true，不可关闭。
  • FR-04-7决策点与三级校验（Spec v1.3 §4.3 唯一口径）：一次 play_decision 对应一个决策点：player_turn 每回合一个计划（1..12 个动作），其余 phase 一个动作。计划逐个执行，每个动作执行前用当前的 legal_actions() 校验：① 语法 = 通过 schemas/decision.schema.json（与 MOD-03 共用）+ kind 必填字段；② 语义 = 动作落在 legal_actions() 内；③ 执行 = step() 的 info["illegal"]。离开 player_turn 后剩余动作直接丢弃（不计非法）；计划执行完仍处于 player_turn → 本决策结束，由 MOD-06 发起下一个决策。
    模板必须把这个逐动作校验的事实写清楚（2026-10-05，M1 验收 F23）：① play_face 的 dieId 与 slotId 是一个配对，必须逐字取自 legal_actions 里出现过的组合，禁止把观测 hand 里的骰子与 slots 里的槽位自行组合；② 同一个 plan 内不得重复使用同一 slotId/dieId；③ use_ability 只能用于还有次数的能力；④ 可选字段不需要时直接省略（不要写 null/"null"/""/-，它们不是合法 id 且会让整条 JSON 校验失败）；⑤ 一次决策 = 一个回合：player_turn 下把本回合想打的牌都放进同一个 plan，最后 end_turn 收尾（过早结束等于把一回合拆成多个决策点）。实测（真实 8B，只读 A/B，每条 24 个 player_turn 观测）：缺 ④ 时首答 schema 通过率 71%、补后 92%；缺 ⑤ 时每决策点合法动作数 1.35、补后 2.32（plan ≥ 2 的比例 39% → 95%），而 steps/decisions 只有启发式的约 1/3（1.17 vs 3.0）会让同一局的决策点数 ×2.5–3。两条模板（harness/prompts/decision.md 与 gamer_rsi/agent/prompts/fixed_v1.md）必须对称保留这五条，否则基线与演化 agent 的提示词强度不可比。
  • FR-04-8legal_actions 判定：每个 env 步之前都重新调用 legal_actions()，禁止缓存。legal_actions() 是精确集合（MOD-01 同 JS，只去掉 abandon_run），语义校验只做集合成员判定；可选字段缺省时（如 targetId）按 GAME D-19 由内核规范化后再比对。
  • FR-04-9重试与轻罚：每个决策最多 3 次尝试（首次 + policy.retry_max=2）。失败尝试包括：MOD-03 E_LLM_SCHEMA_INVALID（L0 修复已在 MOD-03 内耗尽，修复本身不计非法），以及计划中任一动作的 ①②③ 失败。每次失败尝试调用 env.reject(stage, reason, raw, final=False) 触发 reward -= 0.05，观测带上 lastResult（环境状态不变）。重试时：已执行过的动作保留，基于当前观测重新请求计划，{{constraints}} 段写入上次的 error_code + error_detail；采样 seed 换为 derive_seed(run, episode, decision, attempt)，否则温度 0 下会得到相同输出。
  • FR-04-10尝试耗尽 → fallback（本模块不判负）：3 次尝试都失败时，调用 env.reject(..., final=True)，然后由 heuristic_policy 执行 1 个动作（source="fallback"），决策完成。连续 3 个 final=True 的判负只由 MOD-02 负责（truncation_reason="policy_failure"，Spec B-15）。v0.1 按尝试计数、3 次即判负，会让 FR-04-14 的 fallback 永远走不到，已废弃。
  • FR-04-11工具注册表：harness/tools/*.py 中的函数必须用 @harness_tool 注册；被调用工具唯一签名为 rank_actions(obs, candidates, memory) -> list[dict]，签名不符 → E_ACTION_TOOL_SIG 并整体弃用工具目录（退化为恒等排序）。
  • FR-04-12受限加载：工具目录先过 MOD-02 guard.gate() 静态扫描（禁网络 / 文件写 / subprocess / import gamer_rsi.env.* / random / 时间随机），再经 guard.load_harness_tools() 在子进程 worker 中加载执行（Spec B-20）；某文件违规 → 弃用该文件、落 E_ACTION_TOOL_GUARD，其余工具继续可用。
  • FR-04-13工具异常降级：rank_actions() 抛异常、超时（policy.tool_timeout_ms，默认 200，含一次 worker 往返）、返回非 list、返回元素集合与 candidates 不等价 → 捕获、记 E_ACTION_TOOL_FAIL、返回原始候选序（不做部分采纳）。
  • FR-04-14启发式 fallback：触发条件为 E_LLM_UNAVAILABLE / E_LLM_TIMEOUT / 尝试耗尽 / 泄漏阻断。实现为 agent/heuristic.py::heuristic_policy(obs, legal, hints) -> Action，逐行移植 GAME src/game/scripts/bots.js 的 greedy_counter：战斗内按 scorePlay 打分（击杀奖励、克制箭头、需要的光盾与净化、状态权重、自魔化惩罚），没有正分动作时先处理魔化骰（净化 → 重掷 → 弃骰），最后 end_turn；地图、商店、宝箱、事件、锻造按 nodeScore/pickDieDef 等规则处理。只使用 obs-agent 字段与 env.hints()（公开信息）。这份实现同时是 MOD-08 的 heuristic 基线，参考通关率默认局 45.5%（JS，n=200，seed 1–200），Python 版须在 ±3pp 以内。返回可读的 reasoning，如 "heuristic:counter play_face d-0007→slot_1 e-00"。
  • FR-04-15模式与采样覆盖：play 用可演化采样参数且 temperature = clamp(policy.temperature, 0.7, 1.2)；eval 固定 temperature=0.0 加显式 seed（Spec v1.3 §8.1 B-14，不可被 harness/config.json 覆盖；MOD-03 在 mode="eval" 下强制）；baseline_fixed_prompt 用冻结模板与固定采样；baseline_heuristic 不调 LLM。采样 seed = derive_seed("policy", salt, episode_seed, decision_index, attempt, harness_version)（INV-6），禁 random / 时间随机。
  • FR-04-16轨迹字段产出：每步上报 prompt_hash、memory_ids、tool_hash、source、mode、attempts、error_codes，字段名与 §7 一致，交 MOD-09 落盘。

5非功能需求

这一节回答「做得对还不够，还得做得快、做得稳、可复现」。

  • NFR-04-1确定性：MOD-04 及工具目录禁止 import random、时间相关随机、numpy/torch 隐式全局 seed；所有排序使用显式全序键；PYTHONHASHSEED=0 下相同输入产生相同输出；由 MOD-09 guards.py AST 扫描在 CI 拦截。
  • NFR-04-2性能：assemble_prompt() p95 ≤ 15 ms；parse_llm_output() p95 ≤ 1 ms；heuristic_policy() p95 ≤ 1 ms；工具调用硬超时 50 ms；单步 MOD-04 自身开销（不含 LLM）p95 ≤ 25 ms。
  • NFR-04-3可复现：同 obs + harness_version + episode_seed + step_index 重跑得到逐字节相同 prompt_hash；仓库含 golden 快照 tests/golden/agent/policy_prompt_<hash>.txt。
  • NFR-04-4可观测：每步恰好一行 JSONL + 结构化事件（decision/illegal/fallback/tool_call/audit_leak），不自建日志格式（Spec §8.2）。
  • NFR-04-5覆盖率：parser.py 与 prompt 组装纯函数 ≥ 85%；policy.py（含编排分支）≥ 70%。
  • NFR-04-6隔离：仅从 gamer_rsi.sandbox.api 导入环境相关类型，禁止 import gamer_rsi.env.*（INV-1），由 MOD-02 静态检查 + MOD-09 import 门禁双重拦截。

play_decision(env, obs, ctx):
  steps, attempts = [], 0
  while attempts < 1 + cfg.retry_max:                                       # FR-04-9：共 3 次尝试
      attempts += 1
      bundle = assemble_prompt(load_template(cfg.template_path), ctx_of(obs, attempts))   # FR-04-1..4
      if audit.scan_text(bundle.text, surface="prompt"):                    # FR-04-6 强制
          emit("policy.reject", code=E_ACTION_LEAK_BLOCK); break
      try: out = llm.generate_json(bundle.messages, DECISION_SCHEMA, mode=ctx.mode,
                                   seed=derive_seed(ctx.run, ctx.episode, obs["decisionIndex"], attempts))
      except E_LLM_SCHEMA_INVALID as e: steps.append(env_reject(env, "syntax", e, final=False)); obs = env.observe(); continue
      except (E_LLM_UNAVAILABLE, E_LLM_TIMEOUT): return fallback_decision(env, obs, degraded=True)
      plan, err = validate_syntax_and_required(out.parsed, phase=obs["phase"])      # ①
      if err: steps.append(env_reject(env, "syntax", err, final=False)); obs = env.observe(); continue
      ok = True
      for i, action in enumerate(reorder(plan, obs)):                        # FR-04-11..13
          legal = env.legal_actions()                                        # FR-04-8：每步重取
          if not validate_semantic(action, legal)[0]:                        # ②
              steps.append(env_reject(env, "semantic", action, final=False)); ok = False; break
          r = env.step(action); steps.append(record(action, r, i, attempts, "llm"))
          if r.info["illegal"]: ok = False; break                            # ③
          if r.terminated or r.truncated or r.observation["phase"] != "player_turn": break   # 剩余动作丢弃
      obs = env.observe()
      if ok: return DecisionResult(steps=steps, source="llm", attempts=attempts, ...)
  steps.append(env_reject(env, "semantic", "attempts_exhausted", final=True))          # FR-04-10
  return fallback_decision(env, obs, prior_steps=steps)                     # heuristic_policy 执行 1 个动作，source="fallback"

读这段伪代码时注意三个细节：重试前 attempts 会变，所以 seed 会变（否则温度 0 下拿到一样的输出）；离开 player_turn 后剩余动作直接丢弃，不算非法；最终判负的计数在 MOD-02，不在本模块。

10错误处理与降级

错误码统一使用 Spec §8 的 E_ACTION_* / E_LLM_* 前缀。新人重点理解两级失败的区分：一级失败（无 Action 可构造，如 JSON 解析失败）走 reject() 记轻罚；二级失败（动作不合法）优先复用 step() 的自然非法路径。

错误码触发处理
E_ACTION_TEMPLATE模板缺失 / 不可解析 / 缺必需占位符用 decision_fallback.md 继续；连续 2 步仍失败 → 全局 fallback
E_ACTION_PARSEjson.loads 失败（含前后夹散文、截断）一级失败：重试，计非法，走 reject()
E_ACTION_SCHEMAJSON 合法但不过 Schema（缺字段 / 类型错 / 未知 kind / 多余字段）一级失败：同上
E_ACTION_ILLEGAL动作不在 legal_actions() 内二级失败：reject()，不执行动作
E_ACTION_EXEC三级：StepResult.info["illegal"]=True消费 MOD-01 裁决，计数与连续计数，不改判
E_ACTION_LEGAL_NOISElegal_actions() 噪声致合法动作被拒warning + MOD-08 统计，不阻断
E_ACTION_ILLEGAL_STREAK连续非法 ≥ 3判该局失败，terminate_episode=True，停止调 LLM
E_ACTION_TOOL_SIG工具签名 ≠ rank_actions(obs, candidates, memory)弃用整个工具目录，恒等排序
E_ACTION_TOOL_GUARD静态扫描命中禁项（网络 / 写文件 / subprocess / import gamer_rsi.env.* / random）弃用该文件，其余可用
E_ACTION_TOOL_FAIL工具抛异常 / 超时 / 返回不等价捕获 → 原始候选序
E_ACTION_BUDGETObservation 单独超预算丢光 memory/reflections 后仍超 → 直接 heuristic
E_ACTION_FALLBACK重试耗尽启发式出招，source="heuristic"，仍计一次非法
E_ACTION_LEAK_BLOCKMOD-02 泄漏扫描阻断不送 LLM，直接 heuristic，触发 audit_leak 事件
E_LLM_UNAVAILABLE / E_LLM_TIMEOUTMOD-03 抛出（透传，不改写）立即全局 fallback；整局标 degraded=true，该局不计入评估样本（Spec §8.5，P-12）
E_LLM_SCHEMA_INVALIDMOD-03 三级修复耗尽计为该决策的一次失败尝试（FR-04-9），不是局级降级
已裁决（Spec v1.3 P-02 → B-15）：一级失败也要产生带 illegal_reason 的 Observation 与 -0.05，故需 MOD-02 新增 SandboxEnv.reject(*, stage, reason, raw) -> StepResult：不改环境状态、返回当前投影 Observation、info={"illegal":True,"illegal_reason":reason,...}、由 MOD-01 记账 reward=-0.05。若 MOD-02 拒绝该 API，备选方案是由 MOD-06 代记账。
