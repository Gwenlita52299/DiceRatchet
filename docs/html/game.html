01为什么先做一个真游戏

如果训练环境只是一个抽象 MDP，RSI 的结论会依赖“我们自己发明的规则”。先把游戏做成人类可玩、有 golden 快照、能人工通关的产品，训练链路才有可对拍的现实锚点。

规则可玩

掷骰 → 放技能槽 → 结算敌人意图 → 地图/商店/事件/锻造 → 三章十关。

规则可对拍

纯函数内核 + 确定性 RNG + 三个摘要；5 组 golden 记录逐步 digest。

规则可移植

MOD-01 按 GAME-01 的契约做逐位等价 Python 内核，训练不经 HTTP。

事实来源的层级：GAME-00（玩法）→ GAME-01（内核契约）→ GAME-02（配表数值）→ src/game 实现。冲突时以 GAME-00 为准；Python 侧只承诺与 JS 逐字节对拍。

02三层结构：内核 / 后端 / 前端

前端不算规则。战斗伤害、克制倍率、敌人意图都在内核里；前端只做展示与交互，避免「两套规则」。测试 kernel 不依赖 backend/frontend 就是钉这条。

03一回合发生了什么

顺序固定才能对拍。敌人光盾在自身回合开始清零、状态结算、虚弱减半、被动触发——这些顺序写在 GAME-01 §4.2，Python 内核逐步照抄。

配表校验在 kernel/loader.js：ID 规则、悬空引用、学派克制、风险等级与骰面一致性。MOD-01 的 load_tables() 复用同一套规则，所以一份坏配表会在两侧同时被拒。

05从游戏到训练环境

两条路都活着。训练走 Python 内核（快、可审计）；网页版是规则来源与人类复核入口。未来若接视觉模型，也可以直接对网页版训练。
实测基线：hard × 6 关的启发式通关率 45.5%（n=200，seed 1–200），每局 p50 232 env 步 / 96 个决策点。这是 MOD-04 启发式与 MOD-08 基线对照的锚点。

06怎么本地跑一局

# 零 npm 依赖，Node ≥ 18
cd src/game
node server.js                    # → http://127.0.0.1:8080

# 全部测试（49 项）
node --test "tests/**/*.test.js"

# 5 组 golden 重放
node --test "tests/kernel/*.test.js"
  • 前端不硬编码难度/开关：GET /api/config/schema 动态渲染。
  • POST /api/replay 无状态重放，审计与对拍用；与在线对局可逐行比较。
  • 服务端只监听 127.0.0.1，默认端口 8080。
