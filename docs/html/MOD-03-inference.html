MOD-03 · inference

模型推理层 —— L1 层唯一的「模型出口」

把「Mac M5 24GB + 全程离线」的本地大模型推理，收敛成一组可测、可复现、可降级的接口：MOD-04 每回合决策调它要 JSON，MOD-06 / MOD-08 评估时并发调它要确定性。它只负责把 prompt 安全地变成模型输出，绝不为失败偷偷兜底。

版本 v1.2（2026-09-30 17:49，按 Spec v1.4 回填裁决，见 §17） 状态：草案（待复核） 所属里程碑：M1 上游 Spec：模块拆分Spec-GameRSI.md（唯一事实来源） 依赖：MOD-09 infra
背景与目标
8B 模型自由生成 JSON 的语法错误率不可接受；MLX 与 llama.cpp 两条技术路线的差异不能泄漏到上层；24GB 是硬上限，OOM 是必然事件；评估要并发而 LLM 是串行资源；一切随机必须来自显式 seed。
核心职责
定义唯一的 Backend 契约（MLX / llama.cpp / llama-server / Mock 四实现），JSON Schema → GBNF 约束编译，采样参数白名单管控，三级 JSON 修复重试，内存预算前置检查，E_LLM_* 错误码体系。
服务对象
MOD-04 policy（每回合决策 JSON）、MOD-07 evolve（反思等自由文本）、MOD-06 loop（模型常驻复用）、MOD-08 evals（held-out 并发评估）、MOD-09 infra（消费埋点记录）。
关键成功度量
200 条真实固定 prompt 上 generate_json 首答通过率 ≥ 90%、三级全失败率 ≤ 1%；评估模式同 seed 逐字节一致；OOM 以 E_LLM_OOM 可捕获而不崩进程；新增后端零改动上层。

1背景与目标

GameRSI 的决策全部来自本地大模型，而本地推理本身又脆又慢又难复现。MOD-03 就是为了把这件事管起来，它要解决五个具体问题：

  1. JSON 语法错误率不可接受——8B 模型自由生成 JSON 的失败率是计划 §8 的头号风险，必须用约束解码 + 校验 + 修复组合拳压下去。
  2. 两条推理路线的差异上层不得感知——MLX 与 llama.cpp 的能力不同（比如 GBNF 只有 llama.cpp 有），但 MOD-04 不该关心这些。
  3. 24GB 是硬上限——OOM 在 24GB 机器上是必然事件而非异常，必须可预测、可捕获、不崩进程。
  4. 评估要并发、LLM 却是串行资源——held-out 评估要同时跑多局，得有排队与限流机制。
  5. 随机性必须显式可控——INV-6 要求一切随机来自显式 seed，而采样温度本身就是随机性，必须被管控死。

M1 可验收目标

  • 200 条真实固定 prompt 上 generate_json 首答通过率 ≥ 90%、三级全失败率 ≤ 1%。
  • 评估模式同 seed、同配置生成文本逐字节一致（G3）。
  • OOM 以 E_LLM_OOM 可捕获返回，不崩进程。
  • Backend 契约定稿并配一致性测试套件——新增后端零改动上层。

2范围

MOD-03 只管「把 prompt 送进模型、把输出安全拿出来」，其余一律不碰。

✓ 负责（范围内）
  • gamer_rsi/inference/backend.py：Backend Protocol、Message / Usage / GenerationResult / BackendHealth / ModelSpec、MockBackend、BackendManager。
  • gamer_rsi/inference/mlx_backend.py：MLXBackend（mlx-lm 进程内；LoRA 挂载点预留给 MOD-10）。
  • gamer_rsi/inference/llama_backend.py：LlamaCppBackend（进程内）与 LlamaServerBackend（llama-server 子进程 + HTTP + GBNF）。
  • gamer_rsi/inference/schema.py：JSON Schema 子集 → GBNF 编译器、validate()、修复 prompt 渲染（独占拥有，MOD-04 与 harness 都不得覆盖，Spec v1.4 B-28）；加载 schemas/decision.schema.json。
  • configs/models.yaml 模型注册表；采样参数管控、超时/取消、重试退避、token/延迟埋点、E_LLM_* 错误码与降级信号。
✗ 不负责（范围外）
  • 不决定 prompt 内容——那是 MOD-04 的事。
  • 不做动作合法性判断——归 MOD-01 / MOD-04。
  • 不做模型微调——归 MOD-10。
  • 不知道 Observation 结构、legal_actions() 与游戏规则。
  • 不做语义/合法性校验（那是 MOD-04 的第二级）。
  • 不写 runs/**/*.jsonl——只产出埋点记录对象，落盘归 MOD-09。
  • 不做 fallback 到 heuristic 的决策——归 MOD-04 / MOD-06。

4功能需求

每条需求都是可测试的硬约束。

FR-03-01加载幂等 + single-flight：BackendManager.load(model_id) 保证同 id 返回同一实例、只触发一次真实加载；未知 id 直接抛 E_LLM_UNAVAILABLE，不偷偷降级。

FR-03-02卸载要真卸干净：释放权重与 KV（MLX 释放引用 + mx.clear_cache()；server 模式 SIGTERM 子进程），其后 health().state == "unloaded"；未加载时 unload 不报错；async with manager.session(model_id) 退出自动卸载。

FR-03-03生成参数与计量：generate() 支持 max_tokens / stop / seed / temperature / top_p / top_k / repetition_penalty / timeout_ms；Usage 必须含 prompt_tokens / completion_tokens / latency_ms / ttft_ms。

FR-03-04JSON 三级策略按序执行：① 约束解码（后端 GBNF 或 JSON mode）→ ② jsonschema.validate → ③ 带校验错误的修复重试。任一级成功即返回，attempts 记录真实尝试次数（1..max_attempts）。

FR-03-05重试与超时预算：max_attempts 默认 3（首答 + 2 修复）；退避 = retry_backoff_ms × 2^(attempt-1)（默认 200 / 400 ms）；全程受 total_timeout_ms（默认 8000）约束，超时抛 E_LLM_TIMEOUT 且不留半截结果。

FR-03-06每次尝试一条埋点：产出 InferenceCallRecord（§13），由 MOD-09 写 runs/<run_id>/metrics/llm_calls.jsonl，并内嵌进 episodes/<split>/<episode_key>.jsonl 步记录（对齐 Spec §4.5）。

FR-03-07采样白名单 + 评估模式收紧：temperature ∈ [0,1.5]、top_p ∈ (0,1]、top_k ∈ [0,200]、repetition_penalty ∈ [1.0,1.5]；越界抛 E_LLM_BACKEND_ERROR（不静默裁剪）。mode="eval" 额外要求 temperature == 0.0 且 seed is not None（B-14：评估温度统一为 0，harness 不可覆盖；v1.0 的「≤0.3」上限因与 MOD-04 的 0.7 冲突已废弃）。

FR-03-08并发限流 + 预算前置：BackendManager 持 asyncio.Semaphore(max_inflight)（默认 MLX=1、server=4）；acquire 之前做内存预算检查，预计超预算抛 E_LLM_OOM 且不提交推理请求。

FR-03-09只抛码、不兜底：失败一律以 E_LLM_* 异常暴露，GenerationResult.outcome_kind ∈ {"action","degraded","error"}；本模块不自行 fallback，由上层决定。

FR-03-10上下文守卫：prompt_tokens + max_tokens > context_length 时，context_overflow_policy="reject"（默认）抛 E_LLM_CONTEXT_OVERFLOW；"truncate" 则从最早的非 system 消息截断并记 truncated=true。

FR-03-11层级隔离：不得 import gamer_rsi.env.*（INV-1），CI 静态扫描强制。

FR-03-12确定性：同 model_id + prompt + 采样参数 + seed，在同一后端、同一模型文件下，评估模式（temperature=0）生成文本逐字节一致（口径见 NFR-03-01）。

5非功能需求

NFR-03-01确定性（三级口径）：评估模式固定 temperature=0.0, top_p=1.0, top_k=0 + 显式 seed；训练模式 temperature ∈ [0.7,1.0]（计划 §3.3 防确定性窥探），故训练模式不承诺文本级复现。三级口径：L1（硬要求）同后端同模型文件重跑 3 次文本逐字节相同；L2（软要求，不保证）跨后端文本一致——kernel 与量化不同；L3（提交口径）轨迹级可复现以 obs_digest + action JSON 为准，llm_raw 不参与 state_hash（INV-2/INV-6）。

NFR-03-02性能：8B-Q4，prompt ≤ 1024 tok、max_tokens=128：p50 ≤ 1.5 s、p95 ≤ 3 s、吞吐 ≥ 25 tok/s；30B-A3B-Q4 同条件 p95 ≤ 8 s、吞吐 ≥ 12 tok/s。阈值登记在注册表 perf_budget，CI 每日基准超阈告警。

NFR-03-03资源：常驻内存（权重 + KV + 运行时）≤ ram_budget_gb（默认 20.0，24GB 留 4GB 给 Python/环境/OS）；实测值写 runs/<run_id>/config.json#inference.resident_gb_measured。

NFR-03-04可复现：采样参数属 harness/config.json#inference（可演化，被 config_hash 覆盖）；configs/models.yaml 是静态注册表，M1–M3 不参与演化，只允许人工变更并记 CHANGELOG。

NFR-03-05可观测：一次调用 = 一条结构化埋点；禁止自建日志格式（Spec §8.2）。常规日志只存 prompt_digest，原文仅 debug_dump_raw=true 时落 runs/<run_id>/raw/。

NFR-03-06离线：零外网；llama-server 只监听 127.0.0.1；加载前校验权重 sha256，不匹配抛 E_LLM_UNAVAILABLE。

NFR-03-07可维护：新增后端只需实现 5 个方法 + name / model_id 属性；同一套一致性测试套件覆盖全部实现。

6接口契约

这是整个模块的核心：一个 Backend Protocol，四个实现（MLX / llama.cpp / llama-server / Mock）。上层只认这个契约，不认后端。

# gamer_rsi/inference/backend.py
from dataclasses import dataclass, field
from typing import Any, Literal, Protocol, runtime_checkable
OutcomeKind = Literal["action", "degraded", "error"]
BackendName = Literal["mlx", "llama_cpp", "llama_server", "mock"]

@dataclass(frozen=True)
class Message: role: Literal["system", "user", "assistant"]; content: str

@dataclass(frozen=True)
class Usage:
    prompt_tokens: int; completion_tokens: int; latency_ms: int; ttft_ms: int | None = None
    prefill_ms: int | None = None; decode_ms: int | None = None

@dataclass(frozen=True)
class BackendHealth:
    state: Literal["unloaded", "loading", "ready", "degraded", "error"]; backend: BackendName
    model_id: str | None; resident_gb: float | None; inflight: int; last_error_code: str | None

@dataclass(frozen=True)
class GenerationResult:
    text: str; parsed: dict[str, Any] | None; usage: Usage; attempts: int   # attempts ∈ 1..max_attempts
    retry_reasons: list[str]                                                # ["ValidationError:$.action.kind"]
    finish_reason: Literal["stop", "length", "timeout", "error"]; outcome_kind: OutcomeKind
    model_id: str; backend: BackendName; prompt_digest: str                 # "sha256:<hex>"
    raw_texts: list[str] = field(default_factory=list)

@dataclass(frozen=True)
class ModelSpec:                                     # configs/models.yaml 一行的类型化形态
    model_id: str; backend: BackendName; weights_path: str; weights_sha256: str; quantization: str
    tokenizer_path: str | None; context_length: int; kv_cache_bits: int; resident_gb_est: float
    kv_gb_per_1k_tokens: float; max_inflight: int; supports_grammar: bool; supports_json_mode: bool
    default_sampling: dict[str, float | int]; perf_budget: dict[str, float]
    fallback_backend: BackendName | None = None; server_args: list[str] = field(default_factory=list)

@runtime_checkable
class Backend(Protocol):
    """MOD-03 唯一后端契约。实现：MLX / LlamaCpp / LlamaServer / Mock 四者。"""
    name: BackendName          # 只读属性
    model_id: str
    async def load(self, spec: ModelSpec) -> None:
        """加载权重与 tokenizer；幂等。失败抛 E_LLM_LOAD_FAILED / E_LLM_OOM。"""
    async def unload(self) -> None:
        """释放权重、KV 缓存、子进程；幂等。"""
    async def generate(
        self, messages: list[Message], *, max_tokens: int = 256, temperature: float = 1.0,
        top_p: float = 0.95, top_k: int = 0, repetition_penalty: float = 1.0, seed: int | None = None,
        stop: list[str] | None = None, timeout_ms: int = 30_000,
        grammar: str | None = None, json_mode: bool = False,
    ) -> GenerationResult:
        """自由文本生成；每次尝试均记埋点。grammar/json_mode 由 generate_json 注入。"""
    async def generate_json(
        self, messages: list[Message], schema: dict[str, Any], *, max_attempts: int = 3,
        retry_backoff_ms: int = 200, total_timeout_ms: int = 8_000, **sampling: Any,
    ) -> GenerationResult:
        """约束解码 → schema 校验 → 修复重试。全部失败抛 E_LLM_SCHEMA_INVALID。"""
    async def health(self) -> BackendHealth:
        """无副作用探针（不触发推理）。"""

class BackendManager:  # 单例门面（v1.0 误写的父类 BuildManagerFacade 已删除）
    def __init__(self, registry_path: str = "configs/models.yaml", *,
                 mode: Literal["train", "eval"] = "train", ram_budget_gb: float = 20.0,
                 infra: "InfraFacade | None" = None) -> None
    def get(self, model_id: str) -> Backend                         # 已加载则直接返回，否则 E_LLM_UNAVAILABLE
    async def load(self, model_id: str) -> Backend                  # 幂等 + single-flight
    async def unload(self, model_id: str) -> None
    async def unload_all(self) -> None
    def session(self, model_id: str) -> AbstractAsyncContextManager[Backend]   # 退出自动 unload
    def estimate_required_gb(self, model_id: str, *, max_inflight: int, context_length: int) -> float
    async def generate_json(self, model_id: str, messages: list[Message],
                            schema: dict[str, Any], **kwargs: Any) -> GenerationResult
    async def health(self) -> dict[str, BackendHealth]

唯一决策 schema：DECISION_SCHEMA

定义在唯一文件 schemas/decision.schema.json（Spec v1.3 §4.3），本模块与 MOD-04 共用同一文件、不再各自维护。它扁平、无条件关键字，所以 GBNF 可以直接编译；kind 与字段名逐字取自 GAME-01 §4 分派表，kind 对应的必填字段由 MOD-04 的语义层校验。

DECISION_SCHEMA: dict[str, Any] = {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "type": "object", "additionalProperties": False, "required": ["reasoning", "plan"],
    "properties": {
        "reasoning": {"type": "string", "maxLength": 200},
        "plan": {"type": "array", "minItems": 1, "maxItems": 12, "items": {
            "type": "object", "additionalProperties": False, "required": ["kind"],
            "properties": {
                "kind": {"enum": ["play_face", "discard_die", "purify", "use_ability", "end_turn", "map_choose",
                                  "shop_buy", "shop_refresh", "shop_remove", "shop_leave", "event_choose",
                                  "treasure_pick", "forge_pick", "shrine_choose", "rest_choose", "relic_swap"]},
                "dieId": {"type": "string", "maxLength": 16}, "slotId": {"type": "string", "maxLength": 16},
                "faceIndex": {"type": "integer", "minimum": 0, "maximum": 11},
                "targetId": {"type": "string", "maxLength": 16}, "abilityId": {"type": "string", "maxLength": 32},
                "value": {"type": "integer", "minimum": 0, "maximum": 99},
                "nodeId": {"type": "string", "maxLength": 16}, "itemId": {"type": "string", "maxLength": 32},
                "optionId": {"type": "string", "maxLength": 32}, "defId": {"type": "string", "maxLength": 48},
                "candidateId": {"type": "string", "maxLength": 32}, "relicId": {"type": "string", "maxLength": 48}}}}}}

plan 的长度（player_turn 为 1..12，其余 phase 为 1）由 MOD-04 按当前 phase 在语义层校验，不写进 schema——这样 schema 与 phase 无关，可以缓存编译结果。

GBNF 支持子集（compile_grammar()）

支持：type ∈ {object,string,integer,number,boolean,array}、enum、required、additionalProperties:false、maxLength、minimum/maximum、minItems/maxItems。遇到 allOf / if / $ref / oneOf 返回 None（= 无 grammar 可用，这不是错误），自动降级 JSON mode + 运行时 jsonschema 校验；禁止静默忽略关键字（Spec P-09 结案）。DECISION_SCHEMA 必须能编译出 grammar，由单测保证。

两个后端实现的差异（显式声明，不隐藏）

维度MLXBackend（mlx-lm）LlamaCppBackend / LlamaServerBackend
运行形态进程内 mlx_lm.load() + stream_generate()，asyncio.to_thread 不阻塞事件循环进程内 Llama.create_completion；或子进程 llama-server + POST /v1/chat/completions
结构化输出JSON mode：自定义 logits 白名单掩码；无 GBNF（supports_grammar: false）GBNF：LlamaGrammar.from_string(gbnf)；server 模式走请求体 "grammar" 字段
并发max_inflight=1server 模式 --parallel 4 --cont-batching → max_inflight=4；进程内 1
卸载释放引用 + mx.clear_cache() + mx.metal.clear_cache()进程内置 None；server 发 SIGTERM 并 wait()
典型失败Metal OOM → 包装 E_LLM_OOMserver 未就绪/端口占用 → E_LLM_LOAD_FAILED；5xx → E_LLM_BACKEND_ERROR
选型阶段一默认（Apple Silicon 更快、迭代快）阶段二默认（30B MoE GGUF 生态成熟 + GBNF 稳定），需真并发时用 server 模式
两者对上层完全等价：同一份 DECISION_SCHEMA、同一套 GenerationResult、同一组 E_LLM_*；差异只由注册表的 supports_grammar / max_inflight 驱动降级路径。

    perf_budget: {p95_latency_ms: 8000, min_tok_per_s: 12}

内存预算公式

required_gb = resident_gb_est + kv_gb_per_1k_tokens × (context_length/1000) × max_inflight + 1.0（1.0 = 临时缓冲）。required_gb > ram_budget_gb → 在 acquire 前直接拒绝并抛 E_LLM_OOM。代入 30B 模型：

  • 32768/4 → 18.8 + 0.05×32×4 + 1.0 = 26.2 > 20.0（拒绝）
  • 16384/2 → 21.4（拒绝）
  • 8192/1 → 20.2（临界，需实测调 kv_cache_bits=4 或修正 resident_gb_est）
已裁决（Spec v1.3 P-10 → §8.6）：30B-A3B 在 24GB 机器上默认 context_length=8192, max_inflight=1；「评估要并发跑多局」通过局级并发（loop.eval_concurrency 个 episode，默认 2，共享一个串行推理队列）实现，而非模型级批处理——与 Spec §8.6 成本可控一致，并避免 OOM 抖动。

存储落点（均由 MOD-09 写，本模块只产出对象）

  • runs/<run_id>/metrics/llm_calls.jsonl——每次尝试一行（§13）。
  • runs/<run_id>/episodes/<split>/<episode_key>.jsonl——步内嵌 llm_latency_ms / prompt_tokens / completion_tokens / llm_raw（Spec §4.5）。
  • 配置来源 configs/models.yaml + harness/config.json#inference，二者均被 config_hash 覆盖。

无独立数据库。

# gamer_rsi/inference/backend.py::BackendManager.generate_json（伪代码，真实控制流）
async def generate_json(self, model_id, messages, schema, **kw) -> GenerationResult:
    spec = self._spec(model_id)                                     # 未知 → E_LLM_UNAVAILABLE
    sampling = validate_sampling(kw, mode=self.mode, spec=spec)      # FR-03-07，越界即抛
    grammar = compile_grammar(schema) if spec.supports_grammar else None   # None → 降级 JSON mode
    deadline = now_ms() + kw.get("total_timeout_ms", 8000)
    async with self._inflight(spec, messages, sampling):             # FR-03-08，超预算 E_LLM_OOM
        result = await self._attempt_loop(spec, messages, schema, grammar, sampling, deadline)
    log_call(result)                                                 # NFR-03-05
    return result.decorate(model_id=model_id, backend=spec.backend)

async def _attempt_loop(spec, messages, schema, grammar, sampling, deadline) -> GenerationResult:
    convo, raw_texts, retry_reasons = list(messages), [], []
    for attempt in range(1, max_attempts + 1):
        if deadline - now_ms() <= 0: raise E_LLM_TIMEOUT(attempts=attempt - 1)   # 不留半截结果
        try:
            out = await asyncio.wait_for(self._backend.generate(
                convo, grammar=grammar, json_mode=True, **sampling), timeout=(deadline - now_ms()) / 1000)
        except asyncio.TimeoutError: raise E_LLM_TIMEOUT(...)
        except OOMError as e:        raise E_LLM_OOM(...) from e
        raw_texts.append(out.text)
        try:
            parsed = json.loads(out.text); jsonschema.validate(parsed, schema)     # ② 校验
            return make_result(parsed, attempts=attempt, retry_reasons=retry_reasons, usage=out.usage)
        except (json.JSONDecodeError, jsonschema.ValidationError) as e:
            retry_reasons.append(f"{type(e).__name__}:{getattr(e, 'json_path', '$')}")
            if attempt == max_attempts: raise E_LLM_SCHEMA_INVALID(attempts=attempt, reasons=retry_reasons)
            await asyncio.sleep(backoff_ms(attempt) / 1000)            # 200, 400 ms
            convo = repair_messages(messages, bad=out.text, error=render_error(e), schema=schema)  # ③

10错误处理与降级

所有失败都归一到 InferenceError，携带错误码、尝试次数、是否可重试与明细：

# gamer_rsi/inference/errors.py
class InferenceError(RuntimeError):
    code: str; attempts: int; retryable: bool; detail: dict[str, Any]
错误码触发retryable上层行为
E_LLM_UNAVAILABLEmodel_id 不在注册表 / 权重缺失 / sha256 不匹配False立即 fallback heuristic；该局 exclude_reason=E_LLM_UNAVAILABLE
E_LLM_LOAD_FAILED权重加载异常、server 起不来、端口占用True（退避后换 fallback_backend 重试 1 次）仍失败 → fallback heuristic，标注「模型不可用」（Spec §8.5）
E_LLM_OOMMetal/系统 OOM；或预算检查前置拒绝True（降 max_inflight/kv_cache_bits 后重试 1 次）仍失败 → fallback heuristic，run 级 degraded_runs += 1
E_LLM_TIMEOUT超 total_timeout_ms 或 generate_timeout_msTrue（最多 1 次）仍失败 → fallback heuristic；该局不计入评估样本（Spec §8.5）
E_LLM_SCHEMA_INVALID三次尝试后仍不满足 schemaFalse返回 outcome_kind="error"；MOD-04 把它计为该决策的一次失败尝试（Spec §4.3 L0 层：修复过程本身不计非法）
E_LLM_CONTEXT_OVERFLOWprompt_tokens + max_tokens > context_length 且策略 rejectFalseMOD-04 缩短上下文后重试（上下文裁剪策略归 MOD-04）
E_LLM_BACKEND_ERROR采样参数越界、server 5xx、grammar 编译失败且后端无 JSON mode参数类 False / 后端类 True（1 次）参数类直接上报；后端类重试后仍失败 → fallback heuristic

降级契约（三条铁律）

  1. 本模块只抛码，绝不静默兜底——不返回空动作、不猜测 JSON。
  2. outcome_kind="degraded" 仅用于「约束解码不可用但 JSON 校验通过」这类可用但质量降级的情形（如 supports_grammar=false 时纯 JSON mode 一次通过），原因记 degraded_reason。
  3. 局级降级（模型不可用/超时/OOM → heuristic agent）由 MOD-04/06 执行，必须写 episode_end.degraded=true + exclude_reason=<E_LLM_*>，MOD-08 据此把该局从评估样本剔除（Spec §8.5）。已回填（Spec v1.3 §4.5 episode_end 行，P-12）：字段名为 degraded: bool 与 exclude_reason: str|null。
