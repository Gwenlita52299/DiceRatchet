MOD-05 · memory

策略记忆与反思库

把 MOD-06 局末产出的反思文本，转成可检索、可度量、可淘汰、可回滚的结构化记忆，让 MOD-04 组装决策 prompt 时，能按当前 Observation 取出最相关的那几条。

版本 v1.2 状态：草案（待复核） 里程碑 M2（MOD-05/06/07 初版） 上游 Spec v1.4（冲突以 Spec 为准）

⚠️ 本页为手工镜像，不随 PRD 自动生成；本次按 2026-10-14 现状增量修订。

背景与目标
它是「反思注入」演化对象的落地载体，也是 MOD-07 可回滚的演化对象之一。三条硬目标：写入→检索→淘汰→回滚全链路确定性可复现；效用证据只用环境原生胜负；heldout/test 的 seed 永不进入记忆。
核心职责
写入管线（去重 / 冲突裁决 / 原子落盘）、检索打分与预算裁剪、容量与 TTL 生命周期、快照血缘与回滚、INV-5 四拦截点隔离与可观测自检。
服务对象
MOD-04 policy（取记忆注入 prompt）、MOD-06 loop（写反思并回填效用）、MOD-07 evolve（快照 / 回滚）、MOD-08 evals（只读统计）、MOD-09 infra 与审计者（CLI 与泄漏事件定位）。
关键成功度量
retrieve() P95 ≤ 50 ms、add_reflection() P95 ≤ 15 ms（active ≤ 2000）、启动加载 ≤ 2 s、常驻内存 ≤ 64 MB、单文件 ≤ 16 MB；蜜罐泄漏 0 告警、同 seed 逐字节可复现。

1背景与目标

MOD-05 处于 DiceRatchet 的 L1 层，扮演「策略记忆与反思库」的角色。训练时，MOD-06 在每局结束后产出一段反思文本；如果只是把文本原样存下来，既没法按当前局面检索，也没法度量哪条记忆真的有用，更没法在演化走偏时回滚。MOD-05 的工作就是把这段文本转成结构化的 MemoryEntry——带上情境键、标签、正反极性、行动提示——再让它走过一条完整生命周期：

写入→ 去重 / 冲突裁决→ 原子落盘→ 检索取用→ 容量 / TTL 淘汰→ 快照 / 回滚

它同时是两件事的落地载体：项目计划 §5 的「反思注入」演化对象（改进对象 a/c），以及 MOD-07 可回滚的演化对象之一（Spec §3 MOD-05）。

三条目标

  1. 全链路确定性可复现：写入→去重→冲突裁决→检索→淘汰→快照/回滚，每一步都可复算。
  2. 效用证据只用环境原生胜负（Spec INV-7）：避免自证式膨胀——记忆不能只因为「被自己引用过」就显得有价值（调研纪要 §4.1）。
  3. 硬性落实 INV-5：heldout/test 的 seed 与相关信息永不进入记忆，四个拦截点全部可审计。
非目标见 §2.2：本模块只做存储、检索与生命周期，不生成反思文本，也不判定记忆价值。

2范围

✓ 负责（范围内）
  • MemoryEntry / ReflectionEntry schema：JSON Schema 校验 + round-trip，对齐 G5。
  • 写入管线：MOD-06 反思入站 → 结构化抽取 → 去重合并 → 冲突检测 → 原子落盘；以及检索、容量、淘汰与归档。
  • 检索 retrieve(obs, top_k, token_budget)：标签 + BM25 + 可选向量 + 效用 + 时新度打分，预算裁剪与顺序确定性。
  • 快照 memory_v{N}.jsonl 与 harness_version 血缘、回滚命令；INV-5 四拦截点与 audit/ 泄漏事件；阶段一存储选型与换向量库触发阈值。
✗ 不负责（范围外）
  • 生成反思文本——MOD-06 的活。
  • 评估记忆是否有用——MOD-08 提供指标，MOD-07 做取舍。
  • 拼装 prompt——MOD-04。
  • embedding 服务实现——走 MOD-03 embed()。
  • seed 注册表与 split 划分——MOD-09 seeds.yaml + MOD-08。
  • 实现泄漏扫描器——只调 MOD-02 sandbox.audit.scan_text(text, surface="memory")（Spec §4.7）。
  • 消融与记忆价值判定——MOD-08。

3使用方与场景

记忆库有五个调用方，期望各不相同。记住这条分工：MOD-06 只写、MOD-04 只读、MOD-07 管版本、MOD-08 只看统计、MOD-09 与人管审计。

使用方调用点期望
MOD-04 policy每次组装决策 prompt 前retrieve() → 有序、预算内、无泄漏的条目与渲染文本
MOD-06 loop局末反思后 / 局内add_reflection(refl, provenance)；record_usage() 回填引用、采纳与胜负
MOD-07 evolve每代演化前 / 回滚stats()、读快照、snapshot(reason=...)、rollback(v)
MOD-08 evals消融「去反思」只读 stats() 与每代 entry_count，不得写库
MOD-09 infra / 人（审计者）横切 / audit leak配置与统一 JSONL 事件、CLI（§7.4）/ 任一泄漏事件可定位到 reflection_id、entry_id 与命中串

四个典型场景（流程细节见 §8）

  • S1：净化值很低仍在全骰进攻的败局反思 → 抽出 1 条 avoid 记忆并去重合并。
  • S2：第 3 回合敌方意图 purge 9、玩家 virtue=4 → 检索命中「净化值低先放光盾」并置首。
  • S3：同情境但结论相反 → 保守共存，挂上冲突组。
  • S4：harness 回滚到 v6 时，memory rollback --to-version 4 恢复同代记忆。

4功能需求

12 条 FR，按「写进来 → 找出来 → 管生命周期 → 保隔离」的脉络排布。

  • FR-05-1schema：两个 entry 有 JSON Schema（draft 2020-12）；to_json → from_json round-trip 逐字段相等；additionalProperties:false，未知字段拒绝。
  • FR-05-2反思入站与抽取：add_reflection() 仅接受 provenance.split == "train"，否则抛 MemoryIsolationError(E_EVAL_INV5_LEAK)；extract_candidates() 用确定性规则从 ReflectionEntry.text 抽出 ≤ max_candidates_per_reflection 个候选（situation/tags/lesson/polarity/action_hint），无候选时仅存反思、不报错。
  • FR-05-3去重与冲突检测：(situation_key, text_hash) 相同 → 精确合并；sim ≥ 0.85 且 situation_key 相同 → 近似合并（合并不新增行，只累加 outcome_stats 与 merged_from）；同 situation_key、polarity 相反、action_hint.kind 相同（或均 null）→ 冲突，默认两条都 active + conflict_group，检索只返回组内高分者并标注。
  • FR-05-4原子落盘：追加 memory_active.jsonl，每 compact_every 次 tmp+fsync+os.replace 压实；崩溃不得留半行。
  • FR-05-5检索：retrieve(obs, *, top_k, token_budget, tick)（Spec §4.7）按 §6.3 打分，返回 RetrieveResult（entries/scores/tokens/dropped/conflict_groups/elapsed_ms）。
  • FR-05-6顺序与裁剪确定性：排序键 (-round(S,6), entry_id)；S < min_score(0.15) 剔除；预算裁剪跳过超预算条目而不截断文本，dropped[] 记原因。
  • FR-05-7容量、淘汰与 TTL（逻辑时钟，Spec v1.3 §8.1）：tick = 本 run 已完成的训练局序号，由 MOD-06 传入，评估局不推进 tick。active > max_entries 时按 (utility, last_ref_tick, entry_id) 升序淘汰到上限；免疫条件 n_ref ≥ 3 或 age_ticks < min_age_ticks（默认 30，即 1 代）；expires_tick = created_tick + ttl_ticks（默认 300，约 10 代），过期淘汰（evict_reason="ttl"）。
    v1.0 用墙钟（min_age_days=7、ttl_days=90），而一个 run 只持续几小时，于是全部条目都免于淘汰、容量上限永远不生效，重跑时 created_at 不同也破坏了 G3——这正是 v1.1 改用逻辑时钟的原因。
  • FR-05-8效用更新：record_usage(episode_key, memory_ids, outcome, *, adopted_ids) 在局末由 MOD-06 调用一次，更新引用、采纳、胜负计数与 last_ref_tick，按 §6.4 重算 utility。adopted_ids 由 MOD-04 在 DecisionResult 中给出。
  • FR-05-9快照、血缘与回滚：每代（或显式）产出 memory_v{N}.jsonl，header 登记 (memory_version, parent_memory_version, harness_version, generation, config_hash, content_sha256)；rollback(target) 校验 sha256 → 原子替换 active 库 → 新版本号（不回退编号，Spec §8.4 不可重写历史）→ 事件 memory_rollback。
  • FR-05-10INV-5 隔离：§6.5 四个拦截点全部生效，命中即拒写/拒返回并落 audit/leak_events.jsonl。
  • FR-05-11可观测与一致性自检：stats() 返回条目数/版本/去重率/冲突数/淘汰数/命中率；verify() 查行完整性、entry_id 唯一、content_sha256、situation_key 可复算，坏行移入 memory/quarantine.jsonl 记 E_IO_MEMORY_CORRUPT 且不中断 loop。
  • FR-05-12陈旧血缘过滤：条目带写入时 harness_version；检索默认排除 harness_version > current_harness_version 的条目。

5非功能需求

  • NFR-05-1确定性（G3）：打分、排序、淘汰只用逻辑时钟 tick（调用方显式传入），不读墙钟；created_at 只作审计展示，不参与打分、也不计入 content_sha256；禁 import random（MOD-09 AST 守卫）；同 seed 同输入两次 retrieve() 逐字节相同。
  • NFR-05-2性能与内存：active ≤ 2000 时 retrieve() P95 ≤ 50 ms、add_reflection() P95 ≤ 15 ms（不含扫描与 embedding）、启动全量加载 ≤ 2 s、常驻内存 ≤ 64 MB（M5/24GB，纯 Python）。
  • NFR-05-3可复现、稳健与可观测：快照 content_sha256 可跨机复核，config_hash 覆盖全部 memory.* 键；记忆是增强而非依赖，任何写入/检索失败不得让本局失败（§10）；事件单行 JSONL（公共字段 run_id/episode_id/harness_version/memory_version/event/ts），不自建日志格式。
  • NFR-05-4容量：单文件 ≤ 16 MB；单条渲染 ≤ 400 字符；token_budget 默认 900；active 默认上限 2000。

6接口契约

三个文件、一组纯函数。记住两条边界：本模块不接收 seed 与 FullState（检索只吃 ObservationDict）；时间只来自调用方传入的 tick，不注入墙钟。

6.3 打分公式（五项权重全部可配置，键见 §9）

IDF(t)    = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
BM25(q,d) = Σ_{t∈q} IDF(t) * f(t,d)(k1+1) / (f(t,d) + k1(1 - b + b|d|/avgdl));   BM25Norm = BM25/(BM25+1) ∈[0,1)
TagSim    = Σ_{t ∈ tags(obs) ∩ e.tags} w(t) / Σ_{t ∈ tags(obs)} w(t)   # w: phase/intent_kind/counter_arrow=2.0，virtue_bucket/enemy_school/slot_kind=1.0，stage_bucket/node_kind/corrupt_count=0.5
VecSim(e) = (1 + cos(q_vec, e.embedding)) / 2;   Recency = exp(-λ * (tick - e.created_tick))   # 阶段一 w_vec=0 不计算 embedding；λ=0.01/训练局
S(e) = w_tag*TagSim + w_bm25*BM25Norm + w_vec*VecSim + w_util*U(e) + w_rec*Recency + (0.25 if e.situation_key == key(obs))
硬过滤: status != "active" | expires_tick <= tick | (exclude_stale_harness 且 e.harness_version > current)
返回: 剔除 S < min_score(0.15) → 按 (-round(S,6), entry_id) 升序 → 贪心填 token_budget（跳过装不下的、不截断）→ 截到 top_k

冲突组内只保留 S 最高者，被压制者记 dropped[].reason="conflict_suppressed"。

6.4 效用分（证据只用环境原生胜负，INV-7）

p_used = (n_win_adopted+1)/(n_adopted+2);  p_base = (n_win_not_adopted+1)/(n_not_adopted+2)   # Laplace α=1
utility = clip(0.5*(p_used - p_base) + 0.3*log1p(n_ref)/log1p(200) + 0.2*exp(-age_ticks/ttl_ticks), -1.0, 1.0)
# adopted 由 MOD-04 判定并经 DecisionResult.adopted_memory_ids 传给 MOD-06：本局某个决策的计划中存在一个动作，与条目 action_hint 的
# (kind, slotKind, 骰子 school) 三元组一致。v1.0 只比较 kind，而 GAME 中大部分动作都是 play_face，这样判定几乎恒为真。MOD-05 不做语义判断。

6.5 INV-5 拦截点（四个，缺一不可）

#位置机制失败行为
I1 源头add_reflection/add_memory 入口provenance.split == "train" 且 seed ∈ MOD-09 seeds.yaml.train抛 MemoryIsolationError(E_EVAL_INV5_LEAK)，不落盘
I2 文本落盘前逐字段扫 text/lesson/tags/action_hint调 sandbox.audit.scan_text(text, surface="memory")：正则 \bseed\b\s*[:=#]?\s*\d{1,7} + 命中 heldout/test seed 集合的裸整数scan.status="quarantined" → 条目入 memory/quarantine.jsonl，事件入 audit/leak_events.jsonl
I3 兜底snapshot() 与 verify(full=True)infra.guards.seed_token_guard() 复扫全库拒绝出快照（E_EVAL_INV5_LEAK），active 条目标 quarantined
I4 出口retrieve() 返回前对入选条目做廉价字面量复检（覆盖旧快照载入的条目）命中条目丢弃并记事件，不计入返回
反思文本里出现 seed 数字必须由 MOD-02 扫描（I2）拦下；I3/I4 是本模块兜底，不替代 MOD-02。

7数据模型与存储

7.1 文件布局与引擎

runs/<run_id>/reflections/{reflections.jsonl,leak_quarantine.jsonl}   # ReflectionEntry 一局一行（仅 train）；扫描不通过者保留文本供审计
runs/<run_id>/memory/{memory_active.jsonl,memory_evicted.jsonl,memory_v{N}.jsonl,quarantine.jsonl,index.json,memory.lock}
runs/<run_id>/audit/leak_events.jsonl                                 # INV-5 命中事件（MOD-02 审计器读）
runs/<run_id>/metrics/memory.jsonl                                    # §13 埋点

阶段一选型：单文件 JSONL + 全量内存索引（dict[entry_id]、倒排 tag→ids、BM25 倒排 token→ids 与 df）：2000 条量级加载 <2 s、零外部依赖、可肉眼 diff、快照天然是文件。

换库触发阈值（任一满足）→ 第一跳 SQLite FTS5（+sqlite-vec），第二跳 FAISS/LanceDB：① active > 20,000；② retrieve() P95 > 200 ms；③ 启用 embedding 且条目 > 50,000；④ 需要多进程并发写。换库时 MemoryStore 对外签名不变（决策）。

压实与容错：每 compact_every=200 次追加或每次 snapshot() 做 tmp 写 + fsync + os.replace；追加行 ≤4 KB 且自带 \n；读侧遇半行按 E_IO_MEMORY_CORRUPT 截断到最后完整 \n。

快照 header（首行）：

{"_type":"memory_snapshot_header","memory_version":5,"parent_memory_version":4,"harness_version":7,"generation":3,"run_id":"...","created_at":"...","config_hash":"...","store_schema_version":"1.0","entry_count":812,"active_count":640,"reason":"generation_3","content_sha256":"..."}

content_sha256 = 其后所有 _type:"memory_entry" 行按序拼接的 sha256。

7.2 版本与血缘（与 harness_version 的关系）

memory_version 单调递增、永不重写历史；parent_memory_version 指向派生来源（正常代际 = 上一版；回滚 = 目标版本）。每条记忆携带写入时 harness_version，即只属于产生它的 harness 代际：MOD-07 回滚 harness 到 h' 后，harness_version > h' 的条目默认不参与检索（FR-05-12），直到再次被引用确认。血缘三元组 (generation, harness_version, memory_version) 写入 index.json，MOD-08 报告按此对齐「去反思」消融。

7.3 检索输出（给 MOD-04）

render_entries() 每条一行："[combat|low_virtue|defense] 净化值低于 25%…（hint=play_face→defense, conf=0.70, util=0.42）"，按分数顺序 \n 连接；RetrieveResult.text 即 {{memory}} 的填充值。

8关键流程

8.1 写入管线

一条反思进来，先过两道隔离闸，再决定是「合并进既有条目」还是「新写一行」：

add_reflection(refl, provenance)→ I1 准入：split==train 且 seed∈train→ I2 逐字段文本扫描→ 落 reflections.jsonl→ extract_candidates 抽取候选
精确去重(text_hash)→ 近似去重(sim≥0.85)→ 冲突检测(相反极性)→ 追加 memory_active.jsonl + 更新索引→ 超容量淘汰 / 定期压实 
add_reflection(refl, provenance):
  I1: if provenance.split != "train" or provenance.seed not in seeds.train: raise E_EVAL_INV5_LEAK
  I2: scan = audit.scan_text(all_text_fields(refl), surface="memory")    # MOD-02
      if scan.status != "pass": append leak_quarantine + audit/leak_events; return QUARANTINED
  append reflections.jsonl
  for c in extract_candidates(refl, cfg)[: max_candidates_per_reflection]:
      key = situation_key_of(c); hits = index.same_situation(key)
      if any(h.text_hash == c.text_hash for h in hits): merge(survivor(h), c); continue        # 精确重复
      near = [h for h in hits if similarity(h, c) >= cfg.dedup.sim_threshold]                  # 近似重复（默认 0.85）
      if near: merge(survivor(near), c); continue
      conf = [h for h in hits if h.polarity != c.polarity and same_hint_kind(h, c)]             # 冲突：同情境相反结论
      if conf: c.conflict_group = sha1(key + "|" + kind(c))[:12]; 给 conf 同组标记
               if cfg.conflict.auto_supersede and evidence_ok(c, conf):
                   old.status = "superseded"; old.superseded_by = c.entry_id; c.supersedes = old.entry_id
      append memory_active.jsonl; update index
  if active_count > max_entries: evict()
  if appends % compact_every == 0: compact()
  return AddResult(added, merged, conflicted, quarantined, memory_version)

去重度量为 similarity(a,b) = 0.5*Jaccard(tokenize(a.lesson), tokenize(b.lesson)) + 0.5*cos(char3gram_tfidf(a.lesson), char3gram_tfidf(b.lesson))，阈值 sim_threshold=0.85 且要求 situation_key 相同（跨情境的不同结论不算重复）。merge：survivor = utility 高者（并列取 created_tick 小者，再并列取 entry_id 小者），outcome_stats 逐项相加，confidence = max，merged_from += other.entry_id，重算 text_hash/content_sha256，不新增行。

8.2 淘汰与 TTL

evict(tick):  pool = [e for e in active if not (e.n_ref >= 3 or tick - e.created_tick < min_age_ticks)]; for e in sorted(pool, key=(utility, last_ref_tick or -1, entry_id))[: active_count - max_entries]: e.status="evicted"; archive("capacity")
sweep_ttl(tick): for e in active: if e.expires_tick <= tick: e.status="evicted"; archive("ttl")      # 写入与 verify() 顺带触发

8.3 快照 / 回滚

snapshot(reason)→ I3 全库 seed 复扫→ 版本号 N+1→ 写 memory_v{N}.jsonl（header+entries+sha256）→ 更新 index.json 血缘
rollback(target, dry_run)→ 快照缺失？E_IO_SNAPSHOT_MISSING（退出码 2）→ sha256 不符？E_IO_MEMORY_CORRUPT→ dry_run 出差异报告→ 原子替换 active + 新版本号 + 发事件 
snapshot(reason):  I3: seed_token_guard(所有 active 条目)，命中即 E_EVAL_INV5_LEAK 并中止
                   N = index.memory_version + 1；write memory_v{N}.jsonl（header + entries，含 content_sha256）
                   index.json = {memory_version:N, parent:current, harness_version:current, entry_count, active_count}
rollback(target, dry_run): 文件不存在 → E_IO_SNAPSHOT_MISSING（退出码 2）；sha256 不符 → E_IO_MEMORY_CORRUPT
                   dry_run → 返回 report(entries_delta, active_delta, lost_entry_ids)
                   否则原子替换 memory_active.jsonl；写新 header(memory_version=current+1, parent_memory_version=target, reason="rollback_to_v{target}")；发 memory_rollback 事件

S4 时序：MOD-07 判负 → 恢复 harness/version.json 到 v6 → memory.rollback(同代快照) → MOD-07 重跑 heldout 确认 → 报告记录 (generation, harness_version=6, memory_version=6)。

错误码前缀沿用 Spec §8.3（E_IO_* / E_EVAL_*），由 MOD-09 集中登记；标注「新增」者为本 PRD 提出的码。
