### 2.3 建一个「临时 runs_root」的 run，用来实跑免费的两个命令

**关键约束（实测过，别踩）**：`cli_init_run` 会对已存在的 run 目录做 `config_hash` 一致性校验。
对已归档的 run（如 `runs/m2-s32b-smoke-c1-medium6`，它记的是旧配置的 hash）直接指定 `--run-id <那个路径>` 会报：

```
[E_IO_RUN_CONFLICT] run 目录 … 已存在且 config_hash 不一致：93b9bb80f788cb4f != 007029b7866db189   （退出码 2）
```

所以请**新建**一个 run（它会被写成当前配置的 hash），并在里面**合成**最小可用的产物，然后跑：

```bash
export DICERATCHET_INFRA__RUNS_ROOT="$(mktemp -d)/runs"     # 不污染仓库 runs/
export DICERATCHET_ENV__EPISODE__DIFFICULTY=hard
export DICERATCHET_EVAL__N_HELDOUT=20
export MPLCONFIGDIR="$(mktemp -d)"                          # 本机 HOME 不可写，避免 matplotlib 噪声
```

然后依次实跑并**记录退出码**：

1. `eval test --check`（对上面新建的 run）——应为 0，且**不得**创建 `test_attestation.json`。
   再补两例：该代已有存证 ⇒ 非 0；`--attestation /nonexistent/xxx/att.json` ⇒ 非 0。
2. `eval acceptance --sensitivity`（对同一个 run）——应产出 `metrics/acceptance.json`，
   stdout 里同时有 `acceptance` 与 `tol_sensitivity` 两块；**总是退出 0**（它是判定器不是守卫）。
   若该 run 尚无 `generations.csv`，先跑 `eval report` 造一个（这需要 `episodes/` 里有局；
   可以直接从 `tests/fixtures/evals/episodes/heldout/` 复制 fixture 进去）。
3. `scripts/run_m3_rehearsal.sh --plan` ——应打印计划且退出 0。
4. `rehearsal check`（对上面那个**尚不完整**的 run）——它**应当报不合格**，把 6 项判据各自
   的结论记录进报告（这正是「判据是活的」的证据；不要为了让报告好看而伪造产物）。
