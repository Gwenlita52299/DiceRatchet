## 2. 背景：三个缺陷的**已实测**事实（不必重新发现，直接引用）

### F46 —— `eval report` 的 `generation` 不是过滤器
- `load_episode_results(run_dir, split, generation=N, ...)`（`dice_ratchet/evals/harness.py:439`）挑文件只做：`episodes/<split>/*.jsonl` 全 glob（:464）、`seeds` 过滤、`arm`/`exclude_arms` 过滤。**`generation` 只用来贴标签，而且覆盖行里自己的值**：`generation=int(generation if generation is not None else rows[0].get("generation") or 0)`（:478）。
- 真实 run `runs/m2-s32b-smoke-c1-medium6` 实测：文件名 `e-{seed:06d}-g{gen:03d}-{arm}.jsonl`，gen-1 下同时有 `e-002000-g000-parent.jsonl`(40) + `e-002000-g001-parent.jsonl`(40) + `e-002000-g001-cand-af1591e1ad7e.jsonl`(37 有效) ⇒ 台账 `metrics/generations.csv` 的 gen-1 行写 `n=117, win_rate=0.6496, decision=pending`。

- **两层混算**：①跨代（g000-parent + g001-parent + g001-cand）；②同代跨臂（即使按代筛干净，`eval report` 仍把 parent 与 cand 聚成一个数，n=77）。这是 M1 验收 F5「混**臂**聚合」的同类残留（那次只给 `arm` 加了真过滤）。
- 同形函数：`read_episode_protocols`（harness.py:492）、`evaluate_generation` 里的训练窗口读取（harness.py:804）。全部 `grep -n "generation=" dice_ratchet/evals/harness.py` 过一遍。

### F42 —— 每代评估没有检查点（且在半速跑）

- **引擎早就有长跑能力**：`run_eval(spec, resume_results=..., on_result=...)`（harness.py:244）——`resume_results` 已完成局不重跑，`on_result` 每局立刻落盘（F18/F19/F20）。但**只有 MOD-08 的 `baseline --resume` 用上了**（`evals/baselines.py:383` 先 load 已完成局、算 `pending`）。
- **中间那层接不上**：`evaluate_arm`（harness.py:678）**没有** `resume_results`/`on_result` 参数 ⇒ MOD-07 想要也拿不到。
- **顺带发现**：`judge.CandidateEvaluator._evaluate_arm`（`dice_ratchet/evolve/judge.py:390`）**没传 `n_workers`** ⇒ 落到 `evaluate_arm` 的默认 1，即 84 局**串行**；而 gen-000 基线路径传的是 `cfg.evals.n_workers=2`（`loop/generation.py:391`）。

### F45 —— 「4 位数字落 2000–2099/9000–9099 即告警」
- `configs/seeds.yaml`：train `1000–1999`；heldout `2000–2099`（H1 2000–2039 / H2 2040–2079 / H3 2080–2099）；test `9000–9099`。`exposure_guard: {destinations_forbidden: [prompt, memory, reflection], numeric_scan: true, forbidden_tokens: [heldout, H1, H2, H3, "2000-2099", "9000-9099"]}`。

- **两处更正（前一轮的人已经犯过，别再犯）**：
  - 豁免粒度是**行的顶层键**（`spec` 在名单里 ⇒ 整个 `spec` 子树被丢弃），不是叶子键。按叶子键去判断"有残差"会得出错误结论。
  - `LOG_NON_CONTENT_KEYS` 注释里那句「64 位 hex 约 3.7% 概率撞 20XX」**是错的**：实测 20000 个随机 sha256 命中 **0/20000**，真实 run 里 `request_hash`/`response_hash`/`prompt_digest` 各 9200 样本命中 **0**（前后环视把 hex 内部的数字段全排除了）。所以 `request_hash`/`response_hash`/`prompt_digest` 三个键是**按错误论据**加进去的——F45-2 删名单时一并说明。
