## 2. 必须先定的 3 个决策（阻塞 MOD-06 接口）

> 这三项都不是"写代码"，但**不定就会写错接口**。每项都要写回指定文档后才算完成。

### D-1 成本硬约束 `E_gen`（决定 MOD-06 的信号量与冒烟可行性）

- **载体**：`loop.max_episodes_per_generation` —— 它是**全系统唯一的单代成本上限**（`config.py:374` 注释原文「全系统唯一成本上限」），
  训练/冒烟/候选评估各占一部分，合计不得超过它。
- **实测单价**（[M1 验收报告 §14.19](../reviews/2026-10-04-M1验收报告.md)）：单局模型时间 **19.6 min**（n=10 均值）；
  `d_wall / d_model = 1.02` → **`n_workers` 不缩短总墙钟**，`n` 局墙钟 ≈ `n × 单局模型时间`。
- **单代时间 = 该上限 × 19.6 min**（与候选数 `C`、冒烟 `S`、heldout `H` 无关——它们只决定**怎么花**这个预算）：

  | `loop.max_episodes_per_generation` | 单代模型时间 | 备注 |
  |---|---|---|
  | **170**（现默认） | **≈55.5 h** | 与 Spec §8.6 的「165 局 ≈118 h/代」冲突（旧口径按 D=185/t_d=7.9 s 算），**需一并澄清** |
  | **120** | **≈39 h** | 排期 §5 提速项的目标值 |
  | **100** | **≈33 h** | 更激进的迭代速度；需确认信号量是否足够 |

- **相关旋钮**：`loop.k=30`（每 K 局触发演化）、`loop.n_candidates=2`（C）、`loop.smoke_n=5`（S）、
  `loop.heldout_n=40`（H）、`evals.n_heldout=40`。`C`/`S` 决定**候选数与冒烟的分配**，`H` 决定**判据的功效**（见 D-3）。
- **待定值**：`loop.max_episodes_per_generation = ____`、`C = ____`、`S = ____`、`H = ____`。
  推荐起点：**上限 120 / C=1 / S=2 / H=40**（≈39 h/代），并在 §3.2 冒烟里确认 C=1 仍能产出可判定的演化。
- **写回**：Spec §8.6（含澄清「165 局」口径）、排期 §5/§6、`configs/default.yaml`。
  **注意**：`config.py` 只对 `loop.n_candidates == evolve.n_candidates` 做了一致性校验；
  `loop.smoke_n` 与 `evolve.smoke_n`（同为 5）**没有**自动校验，改 `S` 时必须两处同步改，
  否则 `loop` 与 `evolve` 会各按自己的值算。
- **风险**：`C=1` 会削弱"多候选择优"的演化信号 → **必须在 §3.2 的小规模冒烟里先确认 C=1 仍能产出 ≥1 轮可判定的演化**。

### D-2 难度口径（medium × 6 vs hard × 6）

- **已触发**：排期 §6 条款「`fixed_prompt` 通关率 < 5% → 改用 medium × 6」——实测 **0/10 = 0.0%（CI [0.000, 0.278]）**，阈值**已触发**。
- **影响面**：换难度会同时改变基线、`D`（决策点数）、成本模型与 M3 主判据的可比性；**必须在 MOD-06 联调前定**，不能推到 M3。
- **两个选项**：
  - **A. 改 medium × 6**（按条款执行）：需重跑三基线（`random`/`heuristic` 秒级；`fixed_prompt` n=10 ≈3.3 h），并把 Spec §8.6 的参考值（hard×6 启发式 45.5%/D=96）替换为 medium 口径。
  - **B. 留在 hard × 6**：承认基线为 0，并**重设判据**（M3 的"相对基线提升"必须改成更容易达成的形式，例如 `mean_stages_cleared` / `mean_battles_won` 而不是 `win_rate`）。
- **待定**：选 `A` / `B`；若选 A，medium × 6 的 `stage_count` 与 `toggles` 取什么（GAME D-34 已支持）。
- **写回**：Spec §8.6、排期 §6、必要时 `configs/seeds.yaml` 的 basket 定义。

### D-3 统计功效（n 与重复次数）

- **问题**：两次 n=10 的 CI 上限都只有 **~28%**，而 M3 要坐实 **4–5pp** 量级的增益；MOD-08 已写明
  **n=40 时配对 McNemar 最小可判不一致对数 `k=6`**（k=6 双尾 p=0.031，k=5 p=0.0625）。
- **待定**：`H`（heldout n）最终取多少、是否需要 `n_rep > 1`（`evals.determinism.n_rep_nondeterministic=3`）、
  以及 `evolve.gap_threshold=0.15` / `evolve.win_rate_tol=0.0` 是否需要随新 `H` 重标定。
- **写回**：MOD-08 §13（指标与口径）、Spec §8.6、`configs/default.yaml` 的 `loop.heldout_n` 与 `evals.n_heldout`。
- **注意**：`H` 每 +10 局，按 19.6 min/局 ≈ **+3.3 h/代**——功效与成本必须一起定，不能分开定。
  且加 `H` 会**顶到 D-1 的单代上限**：`H` 变大就得同步抬高 `loop.max_episodes_per_generation`，否则 heldout 臂会被预算挤掉。

**阶段出口**：三项都写回文档与 `configs/`，且 `load_config()` 的一致性校验（如 `loop.n_candidates == evolve.n_candidates`）仍然通过。

## 3. 必须先做的 2 项实测

### 3.1 【最高风险】full `PolicyAgent` 的 held-out 基线实测（≈3.3 h）

**为什么是阻断项**：MOD-07 的 **C5 门**是 `evolve.max_illegal_rate = 0.05`、`evolve.max_fallback_rate = 0.10`、
`evolve.max_truncation_rate = 0.05`。而我们目前**唯一的真实 LLM 数据是 `fixed_prompt` 基线**：

| 基线（`runs/m1-real-h1n10b/`） | `illegal_rate` | `fallback_rate` | 相对 C5 门 |
|---|---|---|---|
| `fixed_prompt`（真实 8B + 冻结模板） | **0.3021** | **0.181** | `illegal` **6.0×** 超限、`fallback` **1.8×** 超限 |

- **风险**：若 full `PolicyAgent`（开工具/记忆/反思）也在同一量级，**M2 的每一次演化都会被 C5 直接 reject**
  ——闭环形式上「跑通 ≥1 轮」，实则一个候选都留不下。
- **重要的不确定性（不要直接套用上表）**：`fixed_prompt` 的构建是 `mode="baseline_fixed_prompt"`
  ——`temperature=0.0`、**工具/记忆/反思全关**（F22 的 `fixed_prompt_policy_config`），并且含 **18% 启发式兜底**。
  full agent 是 `temperature` 采样 + 工具/记忆/反思全开，**它的非法率既可能更低也可能更高**，必须实测，不能推断。
- **任务**：
  1. 让 **full `PolicyAgent`**（`harness/prompts/decision.md`，`mode="play"`）在 **H1 子集 seed 2000–2009** 上跑 held-out，
     归档为一条**基线之外的独立 arm**（例如 `arm="baseline-full"` 或专用 run-id），`n=10 / degraded_n=0 / n_dropped=0`；
  2. 读出 `illegal_rate` / `fallback_rate` / `truncation_rate` / `win_rate` / `mean_decisions`；
  3. **用实测值标定 C5**：若三项均达标 → 保留 0.05/0.10/0.05；若有超标 → 二选一：
     a) 按实测上界重设门（例如 `max_illegal_rate=0.35`），并**写明这是"先松开、M3 再收紧"**；
     b) 先修 prompt/机制把非法率压下来（更贵，但保住了门的诊断价值）。
- **注意口径**：`illegal_rate` 的分母是 `steps + illegal_attempts`（`metrics._illegal_rate`），
  与「含非法动作的 LLM 输出占比」（n=10 实测 **733/971 = 75.5%**）**不是同一个数**——报告时两个都要给，别混用。
- **顺带**：`decisions_llm` 与 `fallback` 的逐局字段已就位（M1 的 F22 修复），可直接聚合。

### 3.2 小规模端到端冒烟（配合 D-1，半天内可完成）

- **目的**：在投入全量 M2 编码前，确认 **C=1, S=2** 下闭环能真正走完一轮并产出 diff + 决策记录（M2 验收判据）。
- **做法**：MOD-05/06/07 初版可跑后，用最小配置（`k` 小、`H` 小、`C=1`、`S=2`）跑 **1 代**，检查：
  1. `harness/versions/` 出现新版本且 `version.json.artifact_hash` 非空、`parent` 指向 v0；
  2. `generations.csv` / `report.json` / `report.sha256` 落盘，`generations.csv` 的每代数字可复算；
  3. `audit leak` clean（G4 在 M2 仍需成立）；
  4. 至少一个候选的 gate 判定是**有信息量的**（不是全 reject / 全 accept）。
- **判据**：这一步过了才进全量编码；不过则先回头调 D-1/D-2。
