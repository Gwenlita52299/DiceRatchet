## 0. 一句话

**「起点继承」的判据从「上一代 accept」换成「play 面指纹相同」，代际测量从「每代重测起点」换成「每代只测候选」，拒绝不再重跑而是落一条死路记录并轻量推进版本号。**
每 cycle 局数 **114 → 74**；一代省 ≈40 局 / ≈¥21 / ≈1.7 h；代价是**被接受候选的测量直接成为下一代基线**（选择偏差，见 §6 F70）。

## 1. 用户口径（逐字保留）

> 1. gen-000 基线 用 v0 harness 跑 40 轮 heldout
> 2. cycle 0 用 v0 train 30 轮，得到补丁 P1
> 3. 用 v0+P1 跑 40 轮 heldout，门禁通过，则 v1=v0+P1，后续比较的 heldout 是步骤 3 的 heldout；
>    门禁不通过，则 v1=v0+（仅 p1 不可行的提示词），后续比较的 heldout 继承 v0 的 heldout
> 4. cycle 1 用 v1 train 30 轮，得到补丁 P2
> 5. 用 v1+P2 跑 40 轮 heldout，门禁通过，则 v2=v1+P2，后续比较的 heldout 是步骤 5 的 heldout；
>    门禁不通过，则 v2=v1+（仅 p2 不可行的提示词），后续比较的 heldout 继承 v1 的 heldout
> 6. cycle 2 用 v2 train 30 轮，得到补丁 P3
> 7. 用 v2+P3 跑 40 轮 heldout，门禁通过，则 v3=v2+P3；门禁不通过，则 v3=v2+（仅 p3 不可行的提示词）
> 这里的继承不需要重跑 heldout，直接复用数据即可

补充裁决：**D1 = A**（死路提示词只给提案方看）、**D2 = A**（拒绝产生轻量版本推进 + git commit，不打 tag、不复制全量 `versions/vN/`）。

## 2. 逐步对照：口径 → 代码路径

| 步骤 | 用户口径 | 代码落点（本版） | 关键判据 |
|---|---|---|---|
| ① | gen-000 基线：v0 跑 40 轮 heldout | `loop/generation.py::write_gen000_baseline` → `evals.evaluate_arm(split="heldout", basket=H1, arm="parent")` → 臂归档 `metrics/arms/gen000-heldout-H1-parent.json`；报告新增 `harness_play_hash` | `heldout.n == 40`、`heldout.source == "measured"` |
| ② | cycle 0：v0 train 30 轮 → P1 | 训练相 `LoopOrchestrator._run_training_episode`（**F64：标签 = `state.generation + 1`**）→ 边界 `maybe_run_generation` → `evolve.propose` | 训练局 `generation == 1`、seed ∈ `take("train", 1)` = 1000–1029 |
| ③a | v0+P1 跑 40 轮 heldout，**通过** | `evolve/judge.py::evaluate_candidate`（`cand-<id>` 臂，`_assert_patch_reaches_prompt` 护栏）→ `_finish_report` → `versioning.accept` ⇒ `versions/v1/` + tag `harness-v1` | `report.heldout.source == "measured"`、`report.heldout` **= 候选的数**、`harness_play_hash` 变了 |
| ③b | 不通过 ⇒ `v1 = v0 + 仅 P1 不可行的提示词` | `versioning.write_dead_end`（写 `harness/dead_ends.md`）→ `versioning.record_rejection`（推进指针 v0→v1 + commit，**无快照 / 无 tag**） | `version.json.version == 1`、`versions/v1/` **不存在**、`dead_ends.md` 含该候选 |
| ③c | 后续比较的 heldout **继承 v0 的** | `generation._inherited_parent_heldout(play_hash=…)`：扫更早代找 **同 play_hash 且真有测量** 的那份 ⇒ cycle 1 命中 **gen-000 基线臂** | `heldout.source == "inherited:gen-000"`、`evaluate_arm` 调用数 **0** |
| ④ | cycle 1：v1 train 30 轮 → P2 | 同 ②，`generation == 2`、seed ∈ 1030–1059 | 同 ② |
| ⑤ | v1+P2 heldout；通过 ⇒ `v2=v1+P2`，否则 `v2=v1+提示词` 并继承 v1 的 heldout | 与 ③ 同构；「v1 的 heldout」= ③ 里保留的那份（accept ⇒ 候选臂；reject ⇒ 继续指向 gen-000） | 同 ③ |
| ⑥⑦ | cycle 2：v2 train → P3 → heldout → `v3` | 与 ④⑤ 同构 | 同 ③ |

### 2.1 `play_hash` 是什么、为什么必须有

```
play_hash = sha256( [(相对路径, 文件 sha256)] for 路径 in
                    ("prompts/decision.md", "config.json", "tools/*.py") )
```

* **在 play 面内**：`decision.md`（打法模板）、`config.json`（`agent.policy.*` 采样温度 / `show_intent`、`memory.retrieve.*`）、`tools/*.py`（受限工具）。
* **刻意排除**：`prompts/reflection.md`（学习侧输入：反思 → 记忆 → 下一轮的 `{{memory}}`）、`dead_ends.md`（只给提案方看）。**这条排除正是用户步骤 3 的「`v1 = v0 + 仅提示词`」能在代码上严格成立的原因**：写死路记录**不改变** `play_hash`，所以继承成立。
* **为什么不能再用版本号**：D2=A 之后，**拒绝也推进版本号**（v0 → v1），于是「版本相同 ⇔ 起点相同」两头都不成立。

### 2.2 每 cycle 的局数账（114 → 74）

| 项 | 修复前 | 本版 | 说明 |
|---|---|---|---|
| train | 30 | 30 | 不变（K=30） |
| parent heldout | **40** | **0** | 同 play 面 ⇒ 直接复用（`_inherited_parent_heldout`） |
| parent smoke | 2 | 2 | 不变：冒烟 seed 取**本代训练块末尾**，候选冒烟跑同一批 seed（FR-07-7 同预算配对的前提） |
| 候选 smoke | 2 | 2 | 不变 |
| 候选 heldout | 40 | 40 | 不变 |
| **合计** | **114** | **74** | −35%（≈40 局 ≈¥21 ≈1.7 h 每代） |

三 cycle 主体从 **382 局** 降到 ≈ **262 局**（gen-000 40 + 3×74）。

## 3. 语义变更清单（**取代/收紧了哪些旧裁决**）

| # | 旧口径（出处） | 新口径 | 为什么必须改 |
|---|---|---|---|
| 1 | F57：继承资格 = 「上一代 `decision="accept"` + `harness_version` 相同」（Spec v2.20 / B-78） | **`harness_play_hash` 相同** + 该代真有测量 | D2=A 让拒绝也推进版本号；且旧资格在**全拒**的 run 里让每代都重测起点 40 局 |
| 2 | F57：`heldout` 段**恒取 parent**（Spec v2.20 / B-77） | **本代结束时在役那份 harness 的测量**（accept ⇒ 候选臂；reject ⇒ 起点那份） | 旧口径下「接受了一代」在台账里**永远不可见** ⇒ 判据 1 的「held-out 单调不降」退化成拿起点与起点比的恒真命题 |
| 3 | F57：判据 1 的 `not_applicable` 豁免看 **`harness_version` 相同** | 看 **`play_hash` 相同**（缺该字段的旧 run 回落版本号判据） | 同 #1 |
| 4 | F57：继承的代**不写 heldout 台账行** | **保留**（新口径下「被拒/继承」的代没有新测量，自然不写行；被接受的代**写**行，数字是候选的） | 台账是「每个在役 harness 各一行」的诚实序列；F48「没有测量就不写行」继续成立 |
| 5 | FR-07-15：拒绝 = 不更新 harness | 拒绝 = **轻量推进版本号**（仅 `dead_ends.md` 变化），**仅当确实评估过候选且构成死路** | 用户的 `v1 = v0 + 提示词`；空候选 / 提案失败 / MOD-08 基础设施故障仍不动 harness（F47-D 同一条纪律） |
| 6 | F64 修复前：训练局标签 = `state.generation`（cycle 序号，差 1） | 标签 = **它服务的那一代** | 否则 `train` 段永远筛不到那 30 局，只拿到本代 4 局冒烟 ⇒ C3 的 `win_rate_gap` 建在垃圾上 |

**明确不动**：已花的 ¥197.67 不追回；上一轮 `m3-formal` 的「判据 1 `ok=false`」结论不变。改变的是**判据能不能被满足**——修 F66 + F64 + D-M3-7 之前，「0 accept」既可归因于「补丁无效」也可归因于「补丁从未被测试」；之后不能。

## 6. 复跑建议（付费，需显式点头）
