## 1. 三份报告独立收敛出的同一个判断

**GameRSI 的核心卖点不是「能自进化的 agent」，而是「自进化的增益可以用不可作弊的方式被测量」。** 三个参考项目都没做到这一点：

- **RRSI**：候选代码直接在 worktree 里跑，无沙箱，唯一闸门是 critic 的 LLM 复审；更根本的是**选择用的 evolve set 就是演化集本身**（这正是 INV-5 结构性防住的问题）。
- **Reef**：沙箱依赖 Linux namespace（bubblewrap），官方明确 macOS 必须走 E2B 云沙箱——隔离边界在 Mac 上必然弱一档。
- **Raven**：威胁模型自陈「These guards stop an LLM designer from taking shortcuts, not a determined adversary... in-memory tampering or oracle probing is possible in principle」，设计沙箱「not filesystem/network jailed」；DAG 完成判决是 LLM 自评且 fails open，judge 重评噪声约 1.3pp。

三者都把「评分不可被候选污染」当原则（RRSI 的 `S` 恒为 benchmark 原生指标且 `select_round` 永远按 `S'` 取 argmax；Raven 的 evolver 把打分代码锁进不可变内核 `path_guard.py`），但只有 GameRSI 有 INV-1/2/4/5/7 五条不变量联合保证。**这条应在 README 和 M3 验收报告里作为项目定位讲清楚。**

## 3. 一个必须诚实面对的反向信号（两份报告独立提出）

**GameRSI 选的路线在论文里被证明更慢。**

- Reef 侧：OpenClaw-RL 表 3，改权重的 hybrid RL 需 **10.3** sessions 达到优化效果，而 memory（Mem0）与 skill-evolution 需 **29.7**——约 3 倍差距。
- RRSI 侧：四个先前基线里**三个 OOD 不如不演化**（TTHE −1.7 点）；Meta-Harness evolve 最强（93.0）但 OOD 只 +0.9；且**没有任何已演化 harness 比基线便宜**（AHE 多花 58% token 换 −4.4 点 OOD）。

这不构成否证（GameRSI 的约束就是不改权重），但给出两条硬要求：

1. **MOD-08 必须把「样本效率」和「代价」列为一等指标**并诚实报告。反击弹药：GEPA 用 **678** rollout 打败 GRPO 的 **24,000**（35× 更少）——在不改权重的前提下，prompt 演化路线反而比权重 RL 更样本高效。
2. **M3 验收口径必须校正**：不能靠「每代都拒绝、heldout 单调不降」退化满足（这是白演化）。RRSI 报告建议的完整验收是「**至少 1 次 accept 且 win_rate_gap 达标且代价不超基线**」。同时「train 涨得快」是**警报不是进步**。

## 6. 一处需要裁决的设计张力

**GEPA 的 Pareto 前沿选父**（保「整体平庸但某类问题异常好」的候选）与 **RRSI 的 argmax + 不可补偿准则**（严格按 `S'` 取，平局保留现任）看似冲突，实则可分层共存：

- **探索层（选谁当父）**用 GEPA 的 Pareto 前沿——保持搜索多样性，避免「总选当前最佳」的局部最优（论文图 6a 的失败模式）。
- **利用层（接受谁继任）**用 RRSI 的不可补偿判定表（噪声下限 → 代价规则 → 领域守卫）+ Raven 的三闸门——保证 champion 链单调、可审计。

三份报告其实都指向这个「探索宽松 / 接受严格」的分工：Reef 的演化边界 RFC 把它写成「三类接受策略（无 gate / 赢多输少 / Pareto 前沿）都落到同一条 release chain」，RRSI 的消融证明「接受侧正则不能少」，GEPA 的表 3 证明「选父策略从 SelectBest 换成 Pareto 值 +6.3」。**这是三者合并后最顺的一条主线。**

## 7. 三份报告的分歧与裁决

| 议题 | Reef 报告 | RRSI 报告 | 裁决建议 |
|---|---|---|---|
| gate 的重量 | 「gate 是可选风险策略」，建议 M3 开「无 gate 持续演化」实验臂（ACE 路径） | 必须加代价规则 + 正则化；完全去正则 = 白演化 | **两者不矛盾**：无 gate 臂正好做 RRSI Table 2 的消融对照臂。M3 四臂跑 {去正则, 去提案侧, 去接受侧, 完整}，用数据说话 |
| MOD-05 记忆的定位 | run state，「快照作为附件搭 release chain」，不上链 | 无直接论述；但「learned state is runtime output, never committed to the evolved artifact」同源 | **采纳 Reef 裁决**：记忆正文不入 harness prompt（INV-3 已挡），快照上链作附件，选择逻辑留 MOD-05 |

## 8. 各报告的独立提醒（互不覆盖，都值得做）

- **RRSI**：所有依赖轮次深度的机制必须为 T=3 重标定——退火公式在 T=3 时几乎不动（`[3,3,2]`）、停滞窗口 w=3 = 全 run、剪枝窗口 > T。务实方案是冻结 `b_t=1`，把探索轴从「组件类型」（只有 3 个 kind，一代饱和）换成**失败模式 id**。
- **Reef**：macOS 无 Linux namespace，MOD-02 必须自己定义并记录隔离边界，诚实承认「比 bubblewrap 弱」并把蜜罐/审计当一等公民补偿。
- **Raven**：Raven 的 `patience=10` 终止条件会让「模式坍缩表现为无改进而提前终止」——GameRSI 的坍缩监控必须同时看**行为多样性（动作分布熵）**，不只看分数停滞。
- **RRSI**：M3 漂移控制——H1 跨代复用必然自适应漂移，RRSI 的协议是所有数字对「同窗口重测的 H0」报告。建议每 G 代把 v0/fixed_prompt 基线在 H1 重跑一次（40 局 ≈ 3.3h）。
