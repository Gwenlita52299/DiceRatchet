# 协议口径纠正：P1 应判负，下一轮 heldout 是 v0+P2

> 日期：2026-10-17　　成本：¥0（本文只纠正口径与账本；测量另计）
> 触发：用户指出「v0+P1 如果没通过，下一轮就应该是 v0+P2 做 heldout」
> 依据：[D-M3-7 七步口径](2026-10-14-M3-DM37架构改造与7步对照.md) §1、[M3R2 主体结果](2026-10-17-M3R2-正式实验主体结果.md)

## 0. 一句话

**P1 是 cycle 0 的候选补丁，它在 heldout 上输给裸 v0（0.05 vs 0.175）⇒ 门禁不通过 ⇒ `v1` 必须是 v0，
P1 出局。** 因此 m3r2 里「accept」的那个 harness 是 `v0+P1+P2`（含一个已判负的 P1），**不是**协议里的 `v1`；
协议下下一步要测的是 **`v0+P2`**。

---

## 1. 七步口径逐条对照（问题出在哪一步）

| 步骤 | 协议要求 | m3r2 实际 | 判定 |
|---|---|---|---|
| ① | gen-000：v0 跑 40 heldout | 我们把 **v0+P1** 当成了起点，gen-000 测的是 v0+P1 | ⚠️ 起点被换掉 |
| ② | cycle 0：v0 train 30 → P1 | P1 是**人工**从上一轮三份补丁去重得到的，没有经过 cycle 0 的训练 | ⚠️ P1 来源不同（可接受，但必须走门禁） |
| ③ | v0+P1 跑 40 heldout；**门禁**；不过 ⇒ `v1 = v0`（P1 只留死路提示） | v0+P1 测了 0.05（vs v0 0.175），**但没走门禁**——它被当成"基线"，没有 accept/reject | ❌ **漏了门禁** |
| ④ | cycle 1：v1 train 30 → P2 | 在 v0+P1 上 train 30 → P2 | ❌ 训练起点错了（应在 v0） |
| ⑤ | v1+P2 跑 40 heldout；通过 ⇒ `v2=v1+P2` | 测的是 v0+P1+P2，accept | ❌ 被测 harness 含已判负的 P1 |
| ⑥⑦ | 后续同构 | P3/P4 在 v0+P1(+失败补丁) 上继续 | ❌ 起点同样含 P1 |

**根因**：为了避免重跑 gen-000、把 P1 直接"焊"进了起点（version 0），于是 P1 既没被门禁审过，
也无法在后续版本里被移除。协议要求的是"P1 是一个候选，门禁决定它进不进入 `v1`"。

## 4. 已就绪的测量（¥0 自检已过）

* harness 副本：`runs/m3r3/harness/` = **裸 v0 + P2**（无 P1 的三条规则；version 仍为 0，
  `reason` 写明来源与"P1 判负"）。
* 新命令：`python -m dice_ratchet loop baseline --run-id <id> --harness-dir <dir> --basket H1`
  —— **只测一个 harness 的 heldout，不训练、不演化**，落 `generations/gen-000/report.json` + 臂归档后停下。
* 免费自检（heuristic，不触网）：`m3r3-smoke` 跑通，`n=40 / win_rate=0.325 / truncation=0`，
  与 `heuristic` 基线逐位一致 ⇒ 命令、归档、报告链路正常（随后删除了 smoke run）。
* 正式测量条件：`--agent llm`、`--basket H1`、`memory_version=0`（与裸 v0 的 gen-000 同为**空记忆**，
  避免把导入记忆混进来）、C1 / hard×6 / eval 温度 0。

**成本**：40 局 ≈ **¥33**（按本轮实测 heldout 单价 ¥0.82–0.88/局）；墙钟 ≈1.5 h。

## 5. 判据与后续分支

1. 测 `v0+P2`（40 局）。
2. 与裸 v0 的 0.175 做**配对**（同 40 个 H1 seed）：McNemar + 胜率 CI + stages/hearts/truncation。
   - **通过**（不劣于 v0、且显著优于 v0 或至少持平且 truncation 改善）⇒ `v1 = v0+P2`，
     在役 harness 换成 v0+P2；P2 的 accept 从"含 P1 的 provisional"转正。
   - **不通过** ⇒ `v1 = v0`，P2 也进死路；下一轮从裸 v0 重新训练（协议严格的 cycle 1）。
3. **协议严格的重训是另一个动作**（v0 train 30 → 新 P2' → heldout，≈¥70）：只有在
   `v0+P2` 通过、但我们还想要"由 v0 训练得到的补丁"时才做。当前先用 40 局把「P2 独立于 P1 还有没有效」
   这个更便宜的问题回答掉。
