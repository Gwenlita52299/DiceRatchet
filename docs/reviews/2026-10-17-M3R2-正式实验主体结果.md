`legal_actions` 之间**前置**一段「回合预算（先读再决策）」：

```diff
@@ -9,6 +9,10 @@
 ## 当前观测（唯一事实来源）
 {{observation}}

+## 回合预算（先读再决策）
+- 本局剩余决策预算有限：若观测里出现回合/步数上限或已接近上限，**优先斩杀**而非防守拖延。
```

## 4. 三个必须说清的诚实边界

1. **P1 没有变好，反而变差了**：v0+P1 = 0.05 vs 裸 v0 = 0.175（点估计 −0.125）。
   两个 CI 在 0.165 处**几乎相接但未完全分离**，所以严格说「没有证据表明 P1 有效」而非「已证 P1 有害」。
   这是本轮最重要的意外：**人工语义去重得到的三条规则，在 heldout 上没带来任何增益**。
   被 accept 的 P2 是**相对 P1 这个低起点**的显著提升；相对裸 v0 的 +0.10（0.175→0.275）CI 大幅重叠，
   **不能**声称"超过原始基线"。
2. **仍低于启发式**：`heuristic` 0.325 > P2 0.275（CI 重叠）。判据 2 未满足，与上一轮结论一致。
3. **单 run / n=40**：gen-002/003 的台账读数（0.275）是**继承**的同一份测量（D-M3-7 设计），
   不是两次独立测量；`comparable_pairs=1` 意味着判据 1 只有一对可比。跨轮的 P1-vs-裸 v0 对照
   还差一层口径：两轮的 `config_hash` 不同（旧 run 的 15 个 `env.sandbox.*` 死键在 F73/F75 后被删），
   但 `episode_config_hash` **逐位相同**（`sha256:113728b4…`）⇒ 局的定义没变，差异不来自局配置。

## 6. 范围漂移：原因与修复（已修，防复发）

**现象**：裁决 1 个 cycle，实际 3 个。

**根因**：`scripts/run_m3r2.sh` 把 `TRAIN_SEEDS` 硬编码成上一轮的 `train:1000-1089`（3 块），
而导入只覆盖了第 1 块（1000–1029）⇒ 剩下 60 个 seed 正好触发第 2、3 个 cycle。
脚本 banner 写「本轮只跑 1 个 cycle」而命令给的是 3 块的 seed —— **文字与命令互相矛盾，命令赢了**。

**修复**（本提交）：
- `CYCLES="${M3R2_CYCLES:-1}"`；总代数 = **已导入代数 + CYCLES**；seed 上界由它推出
  （`TRAIN_BASE + K×总代数 − 1`），不再硬编码。
- 新增前置断言：用**生产线自己的** `infra_cli.parse_seeds_spec` 解析 `--seeds`，
  解析出的 seed 数必须**恰好**等于 `K × 总代数`；不符即 fail-closed（退出码 4，不花钱）。
- 已用 `train:1000-1119` 单测该断言：`resolved=120 want=120 ok=True`。

**这笔多花的钱怎么算**：多出的 2 个 cycle（148 局 / ≈¥135 / ≈7.7 h）**不是白花**——它带来
2 条真实死路记录与 2 次独立候选测量（0.075 / 0.175），但**不改变**判据 1 的结论（`accepts=1` 不变）。
报告与产物一起保留，不再重跑。

## 7. 下一步（按优先级，均待裁决）

1. **¥0：解释 P1 的负效应**。用归档轨迹做决策面反事实：P1 三条规则里哪一条把打法带偏了
   （例如"心数 ≤1 优先防御"在 hard×6 下可能把本可斩杀的回合拖成截断/失败）。
   这直接决定下一轮要不要**回退 P1**、只保留 P2。
2. **¥0：复算 P1-vs-裸 v0 的方差**。同一 H1 上裸 v0 已有两轮测量（0.175 / 0.05 的起点是不同 harness），
   可先做零成本的口径核对（是否 eval 温度/seed 完全同源），再决定要不要花 40 局（≈¥21）重测裸 v0。
3. **付费：从 v1（=P1+P2）再走 1 个 cycle**（≈¥65 / ≈3 h）。这是**干净的下一步**——起点已有 0.275 的测量，
   D-M3-7 会直接继承它，只测候选 40 局。
4. **判据 2 仍是最硬的缺口**：0.275 < heuristic 0.325。要过判据 2，需要 harness 至少追平启发式；
   这不是再跑一代能保证的，建议先做 §7.1 的零成本归因。
