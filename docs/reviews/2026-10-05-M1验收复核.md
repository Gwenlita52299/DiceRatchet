### M-3：归档的 `fixed_prompt` 基线**实质上是「LLM + 启发式兜底」的混合体**（P2，口径）

- 原始逐局复算（10 局）：`decisions = 674`（决策点总数）、`decisions_llm = 971`（发生过 LLM 调用的决策点）、
  `steps = 1693`、`fallback_decisions = 122`、`illegal_attempts = 733`。
  - `fallback_rate = 122 / 674 = 0.181` → **约每 5.5 个决策点就有 1 个完全由启发式产出**；
  - `illegal_attempts / decisions_llm = 733 / 971 = 0.755` → **约 4 个 LLM 输出里有 3 个含当时的非法动作**；
  - `steps / decisions = 2.51`（启发式参考 3.0）→ 回合效率仍低于启发式。
- 因此最终归档的 `0/10 = 0.0%` 更准确的读法是：**「8B + 冻结模板 + 18% 启发式兜底」的成功率，
  且其 LLM 输出的动作级不可用率高达 76%**——它同时是「模型不会玩」与「模型动作经常不可用」两条结论的证据。
- 报告 §14.19 披露了这些数字（值得肯定），但 §13.1 的最终判定**未把它作为基线纯度的 caveat** 记入，
  M3 写结论时容易把这条基线当作「纯 LLM 策略」。
- **裁定（2026-10-05，用户）：写入判定。** 处置：在 M1 报告 §13.1「判据 1 达成」后补一句口径 caveat——
  该基线含 **18% 启发式兜底**、**76% 的 LLM 尝试引用当时非法动作**；M3 引用这条基线时必须**同时报告
  `fallback_rate` / `illegal_rate`**，否则「相对基线的增益」可能主要来自「把兜底率降下去」而非策略变强
  （这正是项目计划 §6 第 2 条「可归因」要求所指向的混淆）。
