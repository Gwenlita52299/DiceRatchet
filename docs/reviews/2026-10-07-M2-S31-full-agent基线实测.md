## 3. 根因判定：不是「提示词没给全合法动作」

用同一 env（`make_default_env` + 默认局配置）、同一 assembler（`PolicyAgent.prompt_bundle`），在 seed 2000–2009 的**合法轨迹**上离线复现了 2,220 个决策点的提示词组装：

| 检查 | 结果 | 含义 |
|---|---|---|
| F13 压缩渲染（`legal_actions_compact`）触发次数 | **0 / 2,220** | 模型每个决策点看到的都是**完整** `legal_actions`（含真实 `dieId`/`slotId` 配对） |
| 最大 `token_estimate` | 2,694（预算 3,072） | 距压缩触发线还有 12% 余量，本局型没有 F13 说的笛卡尔积爆炸（最大 36 条合法动作） |
| 非法尝试的动作类型 | `play_face` **643（65.2%）**、`use_ability` 76、`end_turn` 47、其余 <1% | 主因是模板第 6 条已明确警告的 `dieId`×`slotId` **配对**问题 |
| `llm.call` 的 `grammar_used` | **false / 1,892（100%）** | MLX 后端拿不到语法约束（`reason=grammar_unavailable`），语义合法性 100% 靠模型自觉 |

**结论**：0.30 的非法率是 8B 的能力/遵从问题，不是渲染或契约缺陷。能把它压到 0.05 量级的只有两条硬杠杆——**语法约束解码**（MOD-03 工程，当前 MLX 路径不可用）或**提示词/机制改造**（收益未验证）。因此「守住 0.05 门」不能作为 M2 的前置。

## 4. C5 裁决与落点（A + C）

| 分支 | 决定 | 落点 |
|---|---|---|
| **A（现在）先松开** | `max_illegal_rate` 0.05→**0.35**、`max_fallback_rate` 0.10→**0.25**、`max_truncation_rate` 0.05→**0.15**（实测上界 + 余量），并写明是「先松开、M3 再收紧」 | `configs/default.yaml`、`dice_ratchet/infra/config.py`、MOD-07 PRD §8.2/§9、Spec §8.6（B-40） |
| **C（M3）收紧路径** | 绝对门 → **相对门**：`candidate.illegal_rate ≤ parent.illegal_rate + tol`（fallback / truncation 同构），保留「抓退化」的诊断价值；`tol` 待 §3.2 冒烟产出第一批 train/heldout 配对后标定 | 登记 Spec §8.6 **B-41**、MOD-07 PRD §8.2 |

**A 的已知副作用**：0.3016 < 0.35 意味着 C5 对 M2/M3 的候选**不再是约束**（任何候选都过）。这是刻意的取舍——M2 的判据是「产出 ≥1 轮可判定的演化」，C5 的绝对质量门让位于此；M3 由 C 恢复诊断力。

**B 未采纳**：先做语法约束解码/提示词改造再开闭环。理由：D-3 已把 M3 的 4–5pp 判据换轴到 `mean_stages_cleared`（C5 在 M3 的角色是回归保护而非质量门），而语法约束解码是 MOD-03 量级工程且收益未验证，不适合当 M2 的前置。

## 5. 口径与保真度说明（引用本报告数字时的前置）

1. **这是 eval 模式（温度 0.0）的数字，不是训练期采样（0.7）的数字**。检查单 §3.1 设想的是「temperature 采样」，但 C5 实际看到的是 MOD-07 的 held-out 评估，而 `loop/runner.py` 对 held-out 臂恒用 `mode="eval"`（`mode = "train" if split == "train" else "eval"`）。两者不可混用。
2. **arm 名是 `play-llm`**（`play` 命令的既有契约）而非检查单举例的 `baseline-full`；归档用专用 run-id 满足检查单的第二种形式。
3. **未挂 MOD-05 memory**（`play` 的 `PolicyAgent(memory=None)`）。当前记忆库为空、`frozen(v0)` 无内容可检索，故对本测量等价；但严格说它不是「记忆全开」。
4. **n=10 的粒度**：`truncation_rate` 的分辨率是 0.1（1/10），C5 实际作用于 n=40 的候选评估（分辨率 0.025）。量级结论（6× 超限）不受影响，具体值需按 n=40 复核。
5. **跑批期间的未提交改动**：`dice_ratchet/app.py` 的 `play` 增加逐局落盘（`run_eval(on_result=...)`，F18 对齐），只影响落盘时机、不影响任何指标。跑批在提交 `6079e36` 上进行。
